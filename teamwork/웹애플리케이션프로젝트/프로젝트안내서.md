## 1. 프로젝트 개요

### 1.1 목적

실제 프로젝트 수행을 통해 다음 역량을 종합적으로 향상시킵니다.

- **기술 역량**: 교육 과정에서 학습한 기술을 통합 적용
- **도구 활용 능력**: 형상 관리(Git), 협업 도구 등 실무 도구 사용
- **문제 해결 능력**: 개발 과정에서 발생하는 다양한 문제를 스스로 해결
- **협업 능력**: 팀 단위 개발 프로세스 경험 (신입 채용 핵심 평가 요소)

### 1.2 프로젝트 개요

| 항목 | 내용 |
|------|------|
| **프로젝트 형태** | 팀 단위 웹 서비스 개발 |
| **프로젝트 기간** | 1주일 |
| **발표일** | 프로젝트 종료일 |
| **팀 구성** | 팀별 3인 또는 6인 |

### 1.3 진행 원칙

- 멘토와 강사는 **직접 구현에 개입하지 않으며**, 방향 제시와 안내 역할만 수행합니다.
- 문제 상황 발생 시 팀원과 함께 스스로 해결하는 과정이 핵심 학습 경험입니다.
- 역할 분담은 **각 팀원이 모든 기술 스택을 경험**할 수 있도록 기능 단위로 나눕니다.

## 2. 프로젝트 주제 선택

아래 두 가지 주제 중 **팀이 합의하여 하나를 선택**합니다.

---

### 주제 A. 사내 메신저 (Corporate Messenger)

> 기업 내 임직원 간 실시간 소통을 위한 웹 기반 메신저 서비스

**시스템 설명**

직원들이 로그인 후 1:1 채팅 또는 그룹 채팅을 통해 업무 관련 메시지를 주고받을 수 있는 사내 커뮤니케이션 플랫폼입니다.

**핵심 기능 (필수 구현)**

| 기능 영역 | 세부 기능 |
|-----------|-----------|
| 회원 관리 | 직원 회원가입 / 로그인 / 로그아웃 / 프로필 관리 |
| 메신저 | 1:1 채팅 / 그룹 채팅방 생성 및 참여 |
| 조직 관리 | 부서별 직원 조회 / 조직도 표시 |
| 알림 | 새 메시지 알림 표시 |
| 관리자 | 직원 계정 관리 / 부서 관리 |

**선택 구현 기능** (여유 시간에 추가)

- 파일 첨부 (이미지, 문서)
- 메시지 읽음/안읽음 표시
- 채팅방 검색
- 이모지 반응

**확장 영역: 그룹웨어 (Groupware)** (팀 역량에 따라 도전)

> 사내 메신저 기능을 기반으로, 기업 내 업무 전반을 지원하는 그룹웨어로 확장합니다.

| 확장 기능 영역 | 세부 기능 |
|----------------|-----------|
| 전자결재 | 문서 기안 / 결재 라인 설정 / 결재 승인·반려 처리 |
| 전자게시판 | 공지사항 / 부서 게시판 / 댓글 기능 |
| 근태 관리 | 출퇴근 기록 / 연차·휴가 신청 및 승인 |
| 일정 관리 | 개인·팀 캘린더 / 일정 공유 |
| 업무 관리 | 업무 등록 / 담당자 지정 / 진행 현황 추적 |

> 💡 **확장 구현 우선순위**: 전자결재 또는 공지 게시판부터 시작하는 것을 권장합니다. 메신저의 조직/부서 관리 기능과 연계하면 효율적으로 구현할 수 있습니다.

### 주제 B. 재고 관리 프로그램 (Inventory Management System)

> 기업의 상품 입출고 및 재고 현황을 관리하는 웹 기반 재고 관리 시스템

**시스템 설명**

관리자와 담당자가 상품의 입고, 출고, 현재 재고 수량을 실시간으로 파악하고 관리할 수 있는 업무 지원 시스템입니다.

**핵심 기능 (필수 구현)**

| 기능 영역 | 세부 기능 |
|-----------|-----------|
| 회원 관리 | 회원가입 / 로그인 / 로그아웃 / 권한 관리 (관리자/일반) |
| 상품 관리 | 상품 등록 / 조회 / 수정 / 삭제 (CRUD) |
| 재고 관리 | 입고 처리 / 출고 처리 / 재고 수량 조회 |
| 이력 관리 | 입출고 이력 조회 / 필터링 검색 |
| 대시보드 | 재고 현황 요약 / 부족 재고 알림 표시 |

**선택 구현 기능** (여유 시간에 추가)

- 카테고리별 상품 분류
- 재고 수량 임계값 설정 및 경고
- 엑셀 데이터 내보내기
- 거래처(공급업체) 관리

**확장 영역: POS 시스템 (Point of Sale)** (팀 역량에 따라 도전)

> 재고 관리 시스템을 기반으로, 실제 판매 현장에서 사용하는 POS 시스템으로 확장합니다.

| 확장 기능 영역 | 세부 기능 |
|----------------|-----------|
| 판매 처리 | 상품 바코드/검색으로 장바구니 담기 / 수량 조정 / 결제 처리 |
| 결제 수단 | 현금 / 카드 결제 구분 기록 |
| 영수증 | 거래 내역 조회 / 영수증 출력(화면) |
| 판매 통계 | 일별·월별 매출 집계 / 상품별 판매 순위 |
| 재고 연동 | 판매 시 자동 재고 차감 / 재고 부족 경고 |

> 💡 **확장 구현 우선순위**: 판매 처리(장바구니 → 결제) 흐름을 먼저 구현하세요. 재고 관리의 출고 처리 로직을 재사용하여 판매 시 재고 자동 차감과 연동할 수 있습니다.

## 3. 기술 사양

프로젝트에 사용하는 **모든 기술을 반드시 적용**해야 합니다.

### 3.1 적용 기술 스택

| 분류 | 기술 | 버전 |
|------|------|------|
| **언어** | Java | 21 |
| **프레임워크** | Spring Framework (Spring Boot) | 7.x |
| **보안** | Spring Security | Spring Boot 내 포함 버전 |
| **ORM** | Spring Data JPA (Hibernate) | Spring Boot 내 포함 버전 |
| **템플릿 엔진** | Thymeleaf | Spring Boot 내 포함 버전 |
| **데이터베이스** | MariaDB | 최신 안정화 버전 |
| **웹 클라이언트** | HTML5, CSS3, JavaScript, jQuery, Bootstrap | - |

### 3.2 개발 도구

| 분류 | 도구 |
|------|------|
| **IDE** | IntelliJ IDEA (권장) |
| **형상 관리** | Git + GitHub |
| **빌드 도구** | Gradle (권장) 또는 Maven |
| **협업 도구** | Notion (진행 상황 공유) |
| **DB 관리** | DBeaver 또는 HeidiSQL |

### 3.3 주요 기술 적용 포인트

**Spring Security** (인증 및 인가)
- 로그인/로그아웃 처리
- 권한별 페이지 접근 제어 (관리자/일반 사용자)
- CSRF 보호 설정
- 비밀번호 암호화 (BCryptPasswordEncoder)

**Spring Data JPA** (데이터 접근)
- Entity 클래스 설계
- Repository 인터페이스 활용
- JPQL 또는 QueryDSL 활용 (필요 시)
- 연관관계 매핑 (@OneToMany, @ManyToOne 등)

**Thymeleaf** (뷰 템플릿)
- 레이아웃 템플릿 구성 (layout:decorate)
- Spring Security 연동 (`th:sec` 속성)
- 폼 데이터 바인딩
- 조건부 렌더링 및 반복 처리

**MariaDB** (데이터베이스)
- DB 모델링 및 ERD 작성 (필수)
- 정규화 적용
- 인덱스 설계 고려

## 4. 프로젝트 수행 요구사항

### 4.1 필수 요구사항

- [ ] 웹 기반 서비스로 구현할 것
- [ ] 팀원 전원이 모든 기술 스택을 다룰 수 있도록 기능 단위로 역할 분담
- [ ] [3.1 적용 기술 스택]의 **모든 기술**을 코드에 실제 적용
- [ ] 팀 GitHub 저장소를 생성하고, 브랜치 전략(예: feature 브랜치)을 적용하여 관리
- [ ] 정기 팀 미팅을 통해 진행 상황 점검 및 문제 해결

### 4.2 협업 규칙 권장사항

- **일일 스크럼**: 매일 시작 전 15분 간 오늘 할 일, 어제 한 일, 어려운 점 공유
- **코드 리뷰**: Pull Request를 통해 팀원 코드 리뷰 후 merge
- **Notion 활용**: 회의록, 역할 분담, 진행 현황 문서화
- **커밋 컨벤션**: 커밋 메시지 형식 팀 내 합의 후 준수
  - 예: `feat: 로그인 기능 구현`, `fix: 재고 수량 오류 수정`

### 4.3 강사/멘토와의 상호작용

| 구분 | 내용 |
|------|------|
| **강사/멘토 역할** | 방향 제시, 힌트 제공, 코드 직접 작성 ❌ |
| **질문 방법** | 시도한 방법과 발생한 오류를 구체적으로 설명하고 질문 |
| **질문 전 체크** | 공식 문서 확인 → 검색 → 팀원 논의 → 강사 질문 순으로 진행 |
