### Step 1. 대용량 원본 데이터 읽기

압축 파일(약 20MB)은 한 번만 내려받아 저장해 두고, 이후에는 저장된 파일을 다시 사용합니다.
원본은 쉼표가 아닌 **세미콜론(`;`)**으로 구분되어 있고, 결측값이 **`?`** 문자로 적혀 있습니다.
`?`를 결측으로 알려주지 않으면 pandas는 해당 열 전체를 문자열로 읽어 버립니다.

```python
# lab_power_step1_data.py
POWER_URL = "https://archive.ics.uci.edu/static/public/235/individual+household+electric+power+consumption.zip"
ZIP_PATH = Path("household_power_consumption.zip")

NUMERIC_COLUMNS = [
    "Global_active_power", "Global_reactive_power", "Voltage", "Global_intensity",
    "Sub_metering_1", "Sub_metering_2", "Sub_metering_3",
]


def load_household_power() -> pd.DataFrame:
    """UCI 가정 전력 소비 데이터를 1분 간격 DataFrame(DatetimeIndex)으로 반환"""
    if not ZIP_PATH.exists():                      # 20MB — 한 번만 다운로드
        response = requests.get(POWER_URL, timeout=300)
        response.raise_for_status()
        ZIP_PATH.write_bytes(response.content)

    with zipfile.ZipFile(ZIP_PATH) as zf:
        txt_name = [n for n in zf.namelist() if n.endswith(".txt")][0]
        with zf.open(txt_name) as f:
            df = pd.read_csv(
                f,
                sep=";",                                              # 세미콜론 구분
                na_values=["?"],                                      # '?' → NaN
                dtype={c: np.float32 for c in NUMERIC_COLUMNS},       # float64 대신 float32로 메모리 절반
            )

    # 'Date'(일/월/연)와 'Time'을 합쳐 하나의 시간 인덱스로 — format을 지정하면 훨씬 빠름
    df.index = pd.to_datetime(df["Date"] + " " + df["Time"], format="%d/%m/%Y %H:%M:%S")
    df.index.name = "datetime"
    return df.drop(columns=["Date", "Time"])


minute_df = load_household_power()
print(minute_df.shape)                     # (2075259, 7)
print(minute_df.index.min(), "~", minute_df.index.max())
print(f"메모리 사용량: {minute_df.memory_usage(deep=True).sum() / 1024**2:.1f} MB")
minute_df.head()
```

> 💡 `dtype`을 지정하지 않으면 각 수치 열이 `float64`(8바이트)로 읽힙니다. `float32`(4바이트)로 읽으면 메모리가 절반으로 줄고,
> 어차피 PyTorch 모델에는 `float32`로 들어가므로 정밀도 손실도 문제가 되지 않습니다.
>
> 💡 네트워크 제약으로 다운로드가 되지 않으면 브라우저로 zip 파일을 받아 `household_power_consumption.zip`이라는 이름으로

### Step 3. 리샘플링 — 1분 → 1시간

1분 단위로 1주일을 보면 시퀀스 길이가 **10,080**이 되어 RNN이 학습하기 어렵고(4-4절 기울기 소실), 계산량도 매우 큽니다.
예측하려는 것도 "시간대별 사용량"이므로 **1시간 단위로 리샘플링**합니다.

리샘플링에서 중요한 것은 **변수의 성격에 맞게 집계 방법을 고르는 것**입니다.

| 변수 | 성격 | 1시간으로 합치는 방법 |
|---|---|---|
| `Global_active_power` 등 전력·전압·전류 | 순간 **비율(rate)** — kW, V, A | 60분의 **평균** |
| `Sub_metering_1~3` | 1분 동안 쓴 **에너지(양)** — Wh | 60분의 **합계** |

에너지를 단순히 `sum()`으로 합치면 두 가지 문제가 생깁니다. 60분 중 일부가 비어 있으면 합계가 실제보다 작아지고,
60분이 **모두 비어 있으면 결과가 NaN이 아니라 0**이 되어 "전기를 전혀 안 쓴 시간"으로 둔갑합니다.
그래서 **평균 × 60**으로 계산합니다. 이렇게 하면 일부 결측은 자연스럽게 보정되고, 모두 비어 있으면 NaN으로 남습니다.

```python
# 서브미터링으로 잡히지 않는 나머지 가전의 에너지 (Wh/분) — 파생 변수
# Global_active_power(kW) × 1000 / 60 = 1분 동안 쓴 전체 에너지(Wh)
minute_df["Sub_metering_rest"] = (
    minute_df["Global_active_power"] * 1000 / 60
    - minute_df["Sub_metering_1"] - minute_df["Sub_metering_2"] - minute_df["Sub_metering_3"]
)

POWER_COLUMNS = ["Global_active_power", "Global_reactive_power", "Voltage", "Global_intensity"]
ENERGY_COLUMNS = ["Sub_metering_1", "Sub_metering_2", "Sub_metering_3", "Sub_metering_rest"]

hourly = pd.concat([
    minute_df[POWER_COLUMNS].resample("h").mean(),            # 비율 → 평균
    minute_df[ENERGY_COLUMNS].resample("h").mean() * 60,      # 에너지 → 평균 × 60 (= 결측 보정된 합계)
], axis=1).astype(np.float32)

print(f"{len(minute_df):,}행 → {len(hourly):,}행")          # 2,075,259행 → 약 34,600행
print(f"리샘플링 후 결측 비율: {hourly['Global_active_power'].isna().mean() * 100:.2f}%")

del minute_df   # 원본 1분 데이터는 더 이상 필요 없으므로 메모리에서 해제
```

### Step 4. 결측 처리 — 짧은 공백만 채우고, 긴 공백은 남겨두기

2~3시간 정도의 짧은 공백은 앞뒤 값을 이어 **보간**해도 무리가 없습니다. 하지만 며칠씩 이어진 공백을 직선으로 이으면
실제로 존재하지 않았던 "완만한 가짜 패턴"을 모델에게 가르치게 됩니다. 그래서 짧은 공백만 채우고 긴 공백은 NaN으로 남긴 뒤,
Step 6에서 **NaN이 걸친 윈도우를 학습 샘플에서 제외**합니다.

```python
MAX_INTERP_HOURS = 3   # 연속 3시간 이하 공백만 보간

hourly_filled = hourly.interpolate(method="time", limit=MAX_INTERP_HOURS, limit_area="inside")

before = hourly["Global_active_power"].isna().sum()
after = hourly_filled["Global_active_power"].isna().sum()
print(f"결측 시간 수: {before} → {after}  (남은 {after}시간은 긴 공백 — 윈도우 단계에서 제외)")
```

> 💡 `limit=3`만 지정하면 긴 공백의 **앞부분 3시간이 채워지고 나머지만 남습니다.** 공백 전체를 남기고 싶다면
> Step 2의 `gap_id` 방식으로 공백 길이를 구해 긴 공백은 통째로 NaN으로 되돌릴 수 있습니다(추가 과제 5).

### Step 5. 시간 특징 인코딩 — 시각·요일·월

전력 사용량은 하루 주기(시각), 1주일 주기(요일), 1년 주기(월·계절)를 모두 가집니다.
세 가지 모두 순환형 변수이므로 sin/cos로 인코딩합니다(베이징 실습 Step 4와 같은 방법).

```python
features = hourly_filled.copy()
idx = features.index
features["hour_sin"] = np.sin(2 * np.pi * idx.hour / 24)
features["hour_cos"] = np.cos(2 * np.pi * idx.hour / 24)
features["dow_sin"] = np.sin(2 * np.pi * idx.dayofweek / 7)
features["dow_cos"] = np.cos(2 * np.pi * idx.dayofweek / 7)
features["month_sin"] = np.sin(2 * np.pi * (idx.month - 1) / 12)
features["month_cos"] = np.cos(2 * np.pi * (idx.month - 1) / 12)

FEATURE_COLUMNS = features.columns.tolist()
TARGET_COLUMN = "Global_active_power"
target_idx = FEATURE_COLUMNS.index(TARGET_COLUMN)

values = features[FEATURE_COLUMNS].values.astype(np.float32)   # (약 34,600, 14) — NaN 포함
print(values.shape, "타깃 컬럼 인덱스:", target_idx)
```

### Step 6. 정규화와 인덱스 기반 Dataset

#### 6-1. 정규화 — 훈련 구간만 `fit`

`StandardScaler`는 NaN을 무시하고 평균·표준편차를 계산하며, 변환할 때는 NaN을 그대로 둡니다.
그래서 긴 공백이 남아 있어도 앞선 실습과 같은 방식으로 정규화할 수 있습니다.

```python
T = len(values)
train_end, val_end = int(T * 0.7), int(T * 0.85)   # 시간 인덱스 기준 분할 지점

scaler = StandardScaler()
scaler.fit(values[:train_end])                      # 훈련 구간만으로 fit (NaN은 자동으로 무시)
data_scaled = scaler.transform(values).astype(np.float32)   # (T, 14) — NaN 위치는 그대로

y_mean, y_std = scaler.mean_[target_idx], scaler.scale_[target_idx]
target_scaled = data_scaled[:, target_idx]          # (T,)
print("분할 지점:", features.index[train_end], "/", features.index[val_end])
```

#### 6-2. 윈도우를 미리 만들지 않는 이유

4-9절과 베이징 실습에서는 `create_multivariate_windows`로 **모든 윈도우를 미리 만들어** 메모리에 올렸습니다. 이번 설정으로 계산해 보면:

```
윈도우 수 약 34,400개 × 168시간 × 14개 변수 × 4바이트 ≈ 324MB
```

원본 시계열(34,600 × 14 × 4바이트 ≈ 2MB)을 168번 복사하는 셈입니다. 윈도우를 길게 잡거나 1분 단위를 그대로 쓰면 금방 메모리가 부족해집니다.
대신 **윈도우의 시작 위치(정수 인덱스)만 저장**해 두고, `__getitem__`에서 필요할 때마다 원본에서 잘라내면 메모리는 원본 크기만큼만 사용합니다.

#### 6-3. 유효한 시작 위치 찾기와 시간순 분할

```python
WINDOW_SIZE = 168   # 과거 1주일(168시간)
HORIZON = 24        # 향후 24시간을 한 번에 예측 (Direct 방식)
SPAN = WINDOW_SIZE + HORIZON

# 입력(168시간) + 정답(24시간) 구간 안에 NaN이 하나라도 있으면 그 시작 위치는 사용하지 않음
nan_row = np.isnan(data_scaled).any(axis=1)                    # (T,) 시점별 결측 여부
has_nan = sliding_window_view(nan_row, SPAN).any(axis=1)       # (T - SPAN + 1,) — 복사 없이 계산
starts = np.flatnonzero(~has_nan)                              # 유효한 윈도우 시작 위치
print(f"전체 후보 {len(has_nan):,}개 중 유효 {len(starts):,}개 (긴 공백으로 {has_nan.sum():,}개 제외)")

# 분할은 "정답 구간이 어디에 있는가"로 결정 — 세 구간의 정답이 절대 겹치지 않음
target_start = starts + WINDOW_SIZE
train_starts = starts[target_start + HORIZON <= train_end]
val_starts = starts[(target_start >= train_end) & (target_start + HORIZON <= val_end)]
test_starts = starts[target_start >= val_end]
print(f"train={len(train_starts):,}  val={len(val_starts):,}  test={len(test_starts):,}")
```

> 💡 검증·테스트 윈도우의 **입력**은 앞 구간의 끝부분과 겹칠 수 있습니다. 실제 서비스에서도 예측 시점 직전 1주일은 이미 관측된 과거이므로 문제가 없습니다.
> 중요한 것은 **정답(미래 24시간)**이 구간 사이에 섞이지 않는 것입니다.

#### 6-4. 인덱스 기반 Dataset

```python
class WindowIndexDataset(Dataset):
    """전체 시계열은 한 번만 저장하고, 시작 위치로 윈도우를 그때그때 잘라내는 Dataset"""
    def __init__(self, data, target, starts, window_size, horizon):
        self.data = torch.from_numpy(data)       # (T, 14) — 복사 없이 NumPy 메모리 공유
        self.target = torch.from_numpy(target)   # (T,)
        self.starts = starts
        self.window_size = window_size
        self.horizon = horizon

    def __len__(self):
        return len(self.starts)

    def __getitem__(self, idx):
        i = self.starts[idx]
        x = self.data[i : i + self.window_size]                                       # (168, 14)
        y = self.target[i + self.window_size : i + self.window_size + self.horizon]   # (24,)
        return x, y


def make_loader(starts, shuffle):
    ds = WindowIndexDataset(data_scaled, target_scaled, starts, WINDOW_SIZE, HORIZON)
    return DataLoader(ds, batch_size=64, shuffle=shuffle)


train_loader = make_loader(train_starts, shuffle=True)
val_loader = make_loader(val_starts, shuffle=False)
test_loader = make_loader(test_starts, shuffle=False)

xb, yb = next(iter(train_loader))
print(xb.shape, yb.shape)   # torch.Size([64, 168, 14]) torch.Size([64, 24])
```

### Step 7. 모델 — 출력 24개의 Direct 다단계 예측

베이징 실습의 `RecurrentForecaster`에서 **출력층 크기만 1 → 24**로 바꿉니다(4-6절 Direct 방식, 4-8절 추가 과제 4).
마지막 은닉 상태 하나가 향후 24시간 전체를 결정하는 요약 정보가 됩니다.

```
                                          ┌─▶ t+1 시간 사용량
입력 168시간 × 14 ─▶ [RNN] ─▶ h_168 ─▶ [Linear(64 → 24)] ─┼─▶ t+2 시간 사용량
                                          │     ...
                                          └─▶ t+24 시간 사용량
```

```python
class RecurrentForecaster(nn.Module):
    def __init__(self, input_size, horizon=1, hidden_size=64, num_layers=2, dropout=0.2, cell="rnn"):
        super().__init__()
        rnn_cls = {"rnn": nn.RNN, "lstm": nn.LSTM, "gru": nn.GRU}[cell]
        self.rnn = rnn_cls(
            input_size=input_size,
            hidden_size=hidden_size,
            num_layers=num_layers,
            batch_first=True,
            dropout=dropout if num_layers > 1 else 0.0,
        )
        self.fc = nn.Linear(hidden_size, horizon)   # Direct 방식 — 미래 horizon개를 한 번에 출력

    def forward(self, x):
        out, _ = self.rnn(x)
        return self.fc(out[:, -1, :])   # (batch, horizon)


model = RecurrentForecaster(input_size=len(FEATURE_COLUMNS), horizon=HORIZON, cell="rnn").to(device)
print(model)
print(f"총 파라미터 수: {sum(p.numel() for p in model.parameters()):,}")
```

### Step 8. 훈련 — 앞선 실습의 함수 재사용

`train_epoch` / `eval_epoch` / `fit`은 베이징 실습과 같은 코드입니다. 정답이 `(batch, 24)`로 바뀌었지만
`nn.MSELoss`는 모든 원소의 평균을 내므로 코드 수정이 필요 없습니다(24개 시점의 오차를 똑같은 비중으로 학습).

```python
def train_epoch(model, loader, optimizer, criterion, device):
    model.train()
    total_loss = 0.0
    for X_batch, y_batch in loader:
        X_batch, y_batch = X_batch.to(device), y_batch.to(device)
        optimizer.zero_grad()
        loss = criterion(model(X_batch), y_batch)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # 168스텝 BPTT — 클리핑 필수
        optimizer.step()
        total_loss += loss.item() * X_batch.size(0)
    return total_loss / len(loader.dataset)


@torch.no_grad()
def eval_epoch(model, loader, criterion, device):
    model.eval()
    total_loss = 0.0
    for X_batch, y_batch in loader:
        X_batch, y_batch = X_batch.to(device), y_batch.to(device)
        total_loss += criterion(model(X_batch), y_batch).item() * X_batch.size(0)
    return total_loss / len(loader.dataset)


def fit(model, save_path, epochs=30, patience=5):
    criterion = nn.MSELoss()
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
    scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode="min", factor=0.5, patience=2)

    best_val_loss, patience_counter = float("inf"), 0
    history = {"train_loss": [], "val_loss": []}

    for epoch in range(1, epochs + 1):
        train_loss = train_epoch(model, train_loader, optimizer, criterion, device)
        val_loss = eval_epoch(model, val_loader, criterion, device)
        scheduler.step(val_loss)
        history["train_loss"].append(train_loss)
        history["val_loss"].append(val_loss)

        if val_loss < best_val_loss:
            best_val_loss, patience_counter = val_loss, 0
            torch.save(model.state_dict(), save_path)
        else:
            patience_counter += 1
            if patience_counter >= patience:
                print(f"Epoch {epoch}: 조기 종료 (검증 손실 {patience}회 연속 개선 없음)")
                break

        print(f"[Epoch {epoch:3d}] train_loss={train_loss:.5f}  val_loss={val_loss:.5f}")

    model.load_state_dict(torch.load(save_path))
    return history


history = fit(model, "best_rnn_power.pt")
```

#### 9-2. 기준 모델 두 가지

24시간 앞을 내다볼 때는 "지금 값을 그대로 24시간 유지"하는 Persistence가 약해집니다.
전력 사용량처럼 **하루 주기가 뚜렷한** 데이터에서는 "내일 같은 시각 = 오늘 같은 시각"이라는 **계절성 기준 모델(Seasonal Naive)**이 훨씬 강력한 비교 대상입니다.
