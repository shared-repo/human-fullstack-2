## 4-1. RNN 개요 및 적용 분야

### 순차 데이터(Sequential Data)란?

지금까지 다룬 데이터(정형 데이터, 이미지, 문장 단위 텍스트)는 각 샘플을 독립적으로 취급해도 무방했습니다.
반면 아래와 같은 데이터는 **순서 자체에 의미**가 있어, 순서를 무시하면 정보가 손실됩니다.

| 데이터 종류 | 순서의 의미 |
|------------|------------|
| 자연어 문장 | 단어 순서가 바뀌면 뜻이 달라지거나 비문이 됨 |
| 오디오/음성 파형 | 시간 순서가 곧 소리의 흐름 |
| 시계열(주가, 전력 사용량, 센서값) | 과거 값이 미래 값에 영향을 줌 |
| 동영상 프레임 | 프레임 순서가 바뀌면 동작의 의미가 사라짐 |
| 손글씨 궤적, 유전자 서열 | 앞뒤 관계가 핵심 정보 |

### RNN(Recurrent Neural Network)이란?

RNN은 이런 순차 데이터를 다루기 위해 고안된 신경망 구조입니다. 핵심 아이디어는 간단합니다 —
**은닉 상태(Hidden State)라는 "기억"을 유지하며, 매 시점마다 이전까지의 기억과 현재 입력을 함께 처리**합니다.

```
 이전 기억          현재 입력
    │                  │
    ▼                  ▼
  ┌─────────────────────┐
  │   순환(Recurrent)     │  ← 이 블록이 매 시점마다 반복 재사용됨 (같은 가중치)
  │       유닛           │
  └─────────────────────┘
    │                  │
    ▼                  ▼
 새로운 기억          현재 출력
```

이렇게 "시간의 흐름을 따라 정보를 이어받는" 구조 덕분에, RNN은 길이가 정해지지 않은 시퀀스도
동일한 모델로 처리할 수 있습니다. 구체적인 수식과 PyTorch 구현은 4-2절에서 다룹니다.

### RNN의 대표적인 적용 분야

| 분야 | 입력 시퀀스 | 출력 형태 | 대표 예시 |
|------|------------|----------|----------|
| 자연어 처리 | 단어/토큰 시퀀스 | 다음 단어, 분류, 번역 시퀀스 | 기계 번역, 감성 분석, 초기 챗봇(Seq2Seq) |
| 음성 인식·합성 | 오디오 프레임 시퀀스 | 텍스트 / 음성 파형 | 음성 비서, TTS(Text-to-Speech) |
| 시계열 예측 | 과거 관측값 시퀀스 | 미래 값(회귀) | 주가·전력 수요·날씨 예측, 설비 이상 탐지 |
| 이미지 캡셔닝 | 이미지 특징(CNN) + 생성 중인 단어들 | 문장 시퀀스 | CNN(인코더) + RNN(디코더) 결합 구조 |
| 필기·서명 인식 | 펜 궤적 좌표 시퀀스 | 문자 시퀀스 / 궤적 예측 | 손글씨 인식, 서명 검증 |
| 동영상 분석 | 프레임 시퀀스 | 행동 분류, 다음 프레임 예측 | 행동 인식, CCTV 이상 행동 탐지 |

### 오늘날 RNN의 위치

자연어 처리 분야는 최근 대부분 Self-Attention 기반의 트랜스포머(주제 5에서 학습)로 이동했습니다.
하지만 RNN/LSTM/GRU 계열은 다음과 같은 상황에서 여전히 실용적인 선택입니다.

- 시퀀스 길이가 비교적 짧고 규칙적인 시계열 데이터
- 연산 자원이 제한된 임베디드·엣지 환경(적은 파라미터, 빠른 단일 스텝 추론)
- 실시간 스트리밍 데이터를 한 스텝씩 순차적으로 처리해야 하는 경우

이번 주제에서는 RNN의 다양한 적용 분야 중 **시계열 예측(Time Series Forecasting)**에 초점을 맞춰,
대기 중 CO2 농도 데이터를 활용해 전처리 → 모델 구현 → 훈련 → 평가 → API 서비스 배포까지
전체 파이프라인을 직접 구현합니다.

## 4-2. RNN의 구조와 순차 처리 원리

### 왜 MLP/CNN으로는 순차 데이터를 다루기 어려운가

MLP는 입력 크기가 고정되어 있고 각 입력 위치를 독립적인 특징으로 취급합니다.
CNN은 지역적 패턴(공간적 근접성)은 잘 잡지만 "이전 스텝의 정보를 계속 누적해서 기억"하는 구조가 아닙니다.
RNN은 **은닉 상태(Hidden State)**라는 메모리를 통해 이전 스텝의 정보를 다음 스텝으로 전달합니다.

```
       x1        x2        x3        x4
        │         │         │         │
        ▼         ▼         ▼         ▼
h0 ──▶[RNN]──▶h1─[RNN]──▶h2─[RNN]──▶h3─[RNN]──▶h4
        │         │         │         │
        ▼         ▼         ▼         ▼
       y1        y2        y3        y4

h_t = 시점 t까지의 "요약된 기억" — 다음 시점으로 계속 전달됨
```

### 순환 수식

```python
"""
매 시점 t 마다 동일한 가중치(W_xh, W_hh, W_hy)를 반복 적용:

  h_t = tanh(W_xh · x_t + W_hh · h_(t-1) + b_h)   ← 은닉 상태 갱신
  y_t = W_hy · h_t + b_y                           ← 출력 계산 (필요한 시점에만)

핵심: 모든 시점이 '같은' 가중치를 공유한다 (파라미터 공유)
→ 시퀀스 길이가 달라져도 동일한 모델을 적용할 수 있음
"""
```

### PyTorch nn.RNN 직접 통과시켜보기

```python
import torch
import torch.nn as nn

rnn = nn.RNN(
    input_size=1,      # 각 시점에 입력되는 특징 수 (여기선 CO2 농도 1개 값)
    hidden_size=32,     # 은닉 상태의 차원 (기억 용량)
    num_layers=1,
    batch_first=True,   # (batch, seq_len, input_size) 순서 사용
)

sample = torch.randn(4, 12, 1)   # (batch=4, seq_len=12, input_size=1)
output, h_n = rnn(sample)

print(output.shape)  # torch.Size([4, 12, 32])  ← 모든 시점의 은닉 상태
print(h_n.shape)      # torch.Size([1, 4, 32])   ← 마지막 시점의 은닉 상태 (num_layers, batch, hidden)

# 시계열 예측에서는 보통 "마지막 시점의 은닉 상태"만 사용해 다음 값을 예측
last_hidden = output[:, -1, :]   # (4, 32) — output[:, -1, :] 는 h_n[-1]과 동일한 값
```

### 다층(Stacked) RNN과 양방향(Bidirectional) RNN

```python
# 다층 RNN: 은닉 상태를 여러 층으로 쌓아 더 복잡한 패턴 학습
deep_rnn = nn.RNN(input_size=1, hidden_size=32, num_layers=2, batch_first=True)

# 양방향 RNN: 과거→미래 방향뿐 아니라 미래→과거 방향도 함께 학습
# 주의: 시계열 "예측"에서는 미래 시점을 미리 볼 수 없으므로 양방향은 보통 사용하지 않음
# (양방향은 품사 태깅처럼 전체 시퀀스를 이미 알고 있는 분류/라벨링 문제에 적합)
bi_rnn = nn.RNN(input_size=1, hidden_size=32, batch_first=True, bidirectional=True)
sample_out, _ = bi_rnn(sample)
print(sample_out.shape)  # torch.Size([4, 12, 64])  ← 정방향+역방향 은닉상태 concat (32*2)
```

## 4-3. 시계열 데이터의 이해와 전처리

### 시계열 데이터란?

지금까지 다룬 데이터(타이타닉 표, 이미지, 문장)는 각 샘플이 **독립적**이었습니다.
반면 시계열(Time Series) 데이터는 관측값이 **시간 순서에 의존**합니다 — 오늘의 값은 어제, 그저께의 값과 연관되어 있습니다.

```
정형 데이터(타이타닉):  [승객1] [승객2] [승객3] ...  ← 순서 바꿔도 의미 동일
이미지(CNN):            [고양이 사진] [강아지 사진] ...  ← 순서 무관
텍스트(트랜스포머):      "나는 밥을 먹는다"  ← 문장 내부 순서는 중요하지만, 문장 간은 독립적

시계열:  [1월] → [2월] → [3월] → [4월] → ...
         ↑ 순서를 바꾸면 의미가 완전히 달라짐 (시간적 인과관계 존재)
```

### 시계열의 3가지 핵심 특성

| 특성 | 의미 | 예시 |
|------|------|------|
| 추세(Trend) | 장기적으로 증가/감소하는 경향 | 대기 중 CO2 농도의 꾸준한 상승 |
| 계절성(Seasonality) | 일정한 주기로 반복되는 패턴 | 여름철 전력 사용량 증가, 월별 CO2 변동 |
| 정상성(Stationarity) | 평균·분산이 시간에 따라 일정한 성질 | 대부분의 원본 시계열은 비정상성(non-stationary) → 차분(differencing)으로 정상화 |

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import statsmodels.api as sm

# statsmodels에 내장된 CO2 농도 데이터셋 (1958~2001, 주 단위, 별도 다운로드 불필요)
co2_raw = sm.datasets.co2.load_pandas().data
co2 = co2_raw['co2'].resample('ME').mean().ffill()  # 월 단위로 리샘플링 + 결측치 보간

print(co2.shape)       # (526,)
print(co2.head())
# 1958-03-31    316.100
# 1958-04-30    317.200
# 1958-05-31    317.433
# ...

plt.figure(figsize=(10, 4))
plt.plot(co2.index, co2.values)
plt.title("월별 대기 중 CO2 농도 (ppm)")
plt.xlabel("연도")
plt.ylabel("CO2 (ppm)")
plt.tight_layout()
plt.savefig("co2_raw.png")
# → 뚜렷한 상승 추세(Trend) + 1년 주기의 계절성(Seasonality)이 동시에 보임
```

### 지도학습 문제로 변환하기 — 슬라이딩 윈도우(Sliding Window)

RNN도 결국 "입력 X → 출력 y"를 배우는 지도학습입니다. 시계열을 지도학습 데이터로 바꾸려면
**과거 N개 값을 입력(X)**, **다음 값을 정답(y)**으로 잘라내는 슬라이딩 윈도우 기법을 사용합니다.

```
원본 시계열: [v1, v2, v3, v4, v5, v6, v7, ...]

window_size=3 일 때:
  X=[v1,v2,v3] → y=v4
  X=[v2,v3,v4] → y=v5
  X=[v3,v4,v5] → y=v6
  X=[v4,v5,v6] → y=v7
  ...
```

```python
def create_sliding_windows(series: np.ndarray, window_size: int):
    """1차원 시계열 배열을 (X, y) 지도학습 쌍으로 변환"""
    X, y = [], []
    for i in range(len(series) - window_size):
        X.append(series[i : i + window_size])
        y.append(series[i + window_size])
    return np.array(X), np.array(y)

WINDOW_SIZE = 12  # 최근 12개월(1년)을 보고 다음 달을 예측

values = co2.values.astype(np.float32)
X, y = create_sliding_windows(values, WINDOW_SIZE)
print(X.shape, y.shape)  # (514, 12) (514,)
```

### 정규화 — 왜, 그리고 어떻게

RNN은 tanh/sigmoid 활성화를 많이 사용하므로 입력 스케일이 크면 기울기가 쉽게 포화됩니다.
**반드시 훈련 구간의 통계만으로 정규화**해야 합니다(검증/테스트 구간 정보가 스케일러에 섞이면 데이터 누수).

```python
from sklearn.preprocessing import MinMaxScaler

# ⚠️ 시계열은 절대 shuffle하면 안 됨 — 시간 순서를 반드시 유지
train_ratio, val_ratio = 0.7, 0.15
n = len(X)
n_train = int(n * train_ratio)
n_val = int(n * (train_ratio + val_ratio))

X_train_raw, y_train_raw = X[:n_train], y[:n_train]
X_val_raw, y_val_raw = X[n_train:n_val], y[n_train:n_val]
X_test_raw, y_test_raw = X[n_val:], y[n_val:]

# 스케일러는 훈련 구간(X_train_raw)만으로 fit
scaler = MinMaxScaler(feature_range=(-1, 1))
scaler.fit(X_train_raw.reshape(-1, 1))

def scale(arr):
    shape = arr.shape
    return scaler.transform(arr.reshape(-1, 1)).reshape(shape)

X_train, y_train = scale(X_train_raw), scale(y_train_raw.reshape(-1, 1)).reshape(-1)
X_val, y_val = scale(X_val_raw), scale(y_val_raw.reshape(-1, 1)).reshape(-1)
X_test, y_test = scale(X_test_raw), scale(y_test_raw.reshape(-1, 1)).reshape(-1)

print(f"train={len(X_train)}  val={len(X_val)}  test={len(X_test)}")
```

### RNN 입력 형태(Shape) 규칙

PyTorch의 RNN 계열 레이어는 `(batch, seq_len, input_size)` 형태의 3차원 입력을 기대합니다
(`batch_first=True` 기준). 지금 만든 `X`는 `(샘플 수, 12)`인 2차원이므로 `input_size=1` 차원을 추가해야 합니다.

```python
import torch

def to_tensor(X, y):
    X_t = torch.tensor(X, dtype=torch.float32).unsqueeze(-1)  # (N, 12) → (N, 12, 1)
    y_t = torch.tensor(y, dtype=torch.float32).unsqueeze(-1)  # (N,)    → (N, 1)
    return X_t, y_t

X_train_t, y_train_t = to_tensor(X_train, y_train)
print(X_train_t.shape, y_train_t.shape)  # torch.Size([359, 12, 1]) torch.Size([359, 1])
```

## 4-4. RNN의 한계 — 기울기 소실과 LSTM/GRU

### BPTT(Backpropagation Through Time)

RNN은 시간을 펼친(unroll) 만큼 역전파도 시간을 거슬러 올라가며 이루어집니다.
시퀀스 길이가 길어질수록 같은 가중치 `W_hh`가 반복적으로 곱해지며 기울기가 매우 작아지거나(소실) 커집니다(폭주).

```python
"""
기울기 소실 직관:
  ∂h_t/∂h_0 ≈ (W_hh)^t 형태로 근사됨

  |W_hh| < 1 → t가 커질수록 (W_hh)^t → 0   (기울기 소실, Vanishing Gradient)
  |W_hh| > 1 → t가 커질수록 (W_hh)^t → ∞   (기울기 폭주, Exploding Gradient)

결과: 기본 RNN은 약 10~20 스텝 이전의 정보는 거의 기억하지 못함 (장기 의존성 학습 실패)
"""

# 기울기 폭주는 Gradient Clipping으로 완화 가능 (기본 RNN/LSTM/GRU 모두 적용)
# torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

# 기울기 소실은 클리핑으로 해결되지 않음 → 구조 자체를 바꾼 LSTM/GRU가 근본적인 해법
```

### LSTM — 게이트로 장기 기억을 보존

LSTM(Long Short-Term Memory)은 별도의 **셀 상태(Cell State) `C_t`**를 두고,
3개의 게이트(Forget / Input / Output)로 정보를 얼마나 남기고 지울지 학습합니다.

```python
"""
Forget Gate:  f_t = σ(W_f · [h_(t-1), x_t] + b_f)   ← 이전 기억을 얼마나 "잊을지" (0~1)
Input Gate:   i_t = σ(W_i · [h_(t-1), x_t] + b_i)   ← 새 정보를 얼마나 "받아들일지"
Candidate:    C̃_t = tanh(W_c · [h_(t-1), x_t] + b_c) ← 새로 추가할 후보 정보

Cell State:   C_t = f_t ⊙ C_(t-1) + i_t ⊙ C̃_t       ← 핵심! 덧셈으로 기억을 전달 (곱셈 누적이 아님)
                                                        → 기울기가 소실되지 않고 잘 흐름

Output Gate:  o_t = σ(W_o · [h_(t-1), x_t] + b_o)
Hidden State: h_t = o_t ⊙ tanh(C_t)

⊙ 는 원소별 곱(element-wise), σ 는 시그모이드 (0~1 사이 값 → '게이트'로 작동)
"""
```

```
       ┌─────────────────────────────────────────┐
C_(t-1)│──⊗────────────⊕──────────────────────────│──▶ C_t
       │   ↑forget      ↑input×candidate           │
       │   │            │                          │
h_(t-1)│──[Forget]──[Input]──[Candidate]──[Output]─│──▶ h_t
       │                                    ⊗tanh  │
       └─────────────────────────────────────────┘
                          ↑
                         x_t
```

### GRU — LSTM을 단순화

GRU(Gated Recurrent Unit)는 셀 상태를 따로 두지 않고 은닉 상태 하나로 합치며, 게이트도 2개(Reset/Update)로 줄인 구조입니다.

```python
"""
Reset Gate:   r_t = σ(W_r · [h_(t-1), x_t] + b_r)   ← 이전 은닉 상태를 얼마나 "무시할지"
Update Gate:  z_t = σ(W_z · [h_(t-1), x_t] + b_z)   ← 이전 정보 유지 vs 새 정보 반영 비율

Candidate:    h̃_t = tanh(W_h · [r_t ⊙ h_(t-1), x_t] + b_h)
Hidden State: h_t = (1 - z_t) ⊙ h_(t-1) + z_t ⊙ h̃_t   ← LSTM의 Cell State 갱신과 유사한 원리
"""
```

### RNN vs LSTM vs GRU 비교

| 항목 | RNN | LSTM | GRU |
|------|-----|------|-----|
| 게이트 수 | 없음 | 3개 (Forget/Input/Output) | 2개 (Reset/Update) |
| 별도 셀 상태 | 없음 | 있음 (`C_t`) | 없음 (은닉 상태에 통합) |
| 파라미터 수(동일 hidden_size) | 1× | 약 4× | 약 3× |
| 장기 의존성 학습 | 취약 | 강함 | 강함 (LSTM과 비슷하거나 근소하게 낮음) |
| 학습 속도 | 빠름 | 느림 | LSTM보다 다소 빠름 |
| 실전 선택 기준 | 매우 짧은 시퀀스, 베이스라인 | 데이터가 충분하고 성능 최우선 | 데이터가 적거나 속도가 중요할 때 |

```python
import torch.nn as nn

INPUT_SIZE, HIDDEN_SIZE = 1, 32

rnn_layer = nn.RNN(INPUT_SIZE, HIDDEN_SIZE, batch_first=True)
lstm_layer = nn.LSTM(INPUT_SIZE, HIDDEN_SIZE, batch_first=True)
gru_layer = nn.GRU(INPUT_SIZE, HIDDEN_SIZE, batch_first=True)

for name, layer in [("RNN", rnn_layer), ("LSTM", lstm_layer), ("GRU", gru_layer)]:
    n_params = sum(p.numel() for p in layer.parameters())
    print(f"{name}: {n_params:,} 파라미터")
# RNN:  1,088 파라미터
# LSTM: 4,352 파라미터   (RNN의 정확히 4배 — 게이트 4개 분량: forget/input/candidate/output)
# GRU:  3,264 파라미터   (RNN의 정확히 3배 — 게이트 3개 분량: reset/update/candidate)

# LSTM의 forward는 (output, (h_n, c_n)) 튜플을 반환 — c_n(셀 상태)이 추가로 존재
sample = torch.randn(4, 12, 1)
lstm_out, (h_n, c_n) = lstm_layer(sample)
print(lstm_out.shape, h_n.shape, c_n.shape)
# torch.Size([4, 12, 32]) torch.Size([1, 4, 32]) torch.Size([1, 4, 32])
```

### 모델 정의 — LSTM 기반 예측기

```python
class LSTMForecaster(nn.Module):
    def __init__(self, input_size=1, hidden_size=64, num_layers=2, dropout=0.2):
        super().__init__()
        self.lstm = nn.LSTM(
            input_size=input_size,
            hidden_size=hidden_size,
            num_layers=num_layers,
            batch_first=True,
            dropout=dropout if num_layers > 1 else 0.0,  # 단일 층이면 dropout 무의미
        )
        self.fc = nn.Linear(hidden_size, 1)  # 마지막 은닉 상태 → 다음 값 1개 예측

    def forward(self, x):
        # x: (batch, seq_len, input_size)
        lstm_out, (h_n, c_n) = self.lstm(x)
        last_hidden = lstm_out[:, -1, :]   # 마지막 시점의 은닉 상태만 사용 (batch, hidden_size)
        return self.fc(last_hidden)         # (batch, 1)

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = LSTMForecaster(input_size=1, hidden_size=64, num_layers=2).to(device)
print(model)

n_params = sum(p.numel() for p in model.parameters())
print(f"총 파라미터 수: {n_params:,}")  # 약 84,000개
```

### 훈련 루프 구현

```python
def train_epoch(model, loader, optimizer, criterion, device):
    model.train()
    total_loss = 0.0
    for X_batch, y_batch in loader:
        X_batch, y_batch = X_batch.to(device), y_batch.to(device)
        optimizer.zero_grad()
        pred = model(X_batch)
        loss = criterion(pred, y_batch)
        loss.backward()
        # RNN 계열은 기울기 폭주 방지를 위해 클리핑을 관례적으로 적용
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimizer.step()
        total_loss += loss.item() * X_batch.size(0)
    return total_loss / len(loader.dataset)

@torch.no_grad()
def eval_epoch(model, loader, criterion, device):
    model.eval()
    total_loss = 0.0
    for X_batch, y_batch in loader:
        X_batch, y_batch = X_batch.to(device), y_batch.to(device)
        pred = model(X_batch)
        loss = criterion(pred, y_batch)
        total_loss += loss.item() * X_batch.size(0)
    return total_loss / len(loader.dataset)

criterion = nn.MSELoss()          # 회귀 문제 — 평균 제곱 오차
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode="min", factor=0.5, patience=5)

EPOCHS = 100
best_val_loss = float("inf")
patience, patience_counter = 15, 0
history = {"train_loss": [], "val_loss": []}

for epoch in range(1, EPOCHS + 1):
    train_loss = train_epoch(model, train_loader, optimizer, criterion, device)
    val_loss = eval_epoch(model, val_loader, criterion, device)
    scheduler.step(val_loss)

    history["train_loss"].append(train_loss)
    history["val_loss"].append(val_loss)

    if val_loss < best_val_loss:
        best_val_loss = val_loss
        patience_counter = 0
        torch.save(model.state_dict(), "best_lstm_co2.pt")
    else:
        patience_counter += 1
        if patience_counter >= patience:
            print(f"Epoch {epoch}: 조기 종료 (검증 손실 {patience}회 연속 개선 없음)")
            break

    if epoch % 10 == 0 or epoch == 1:
        print(f"[Epoch {epoch:3d}] train_loss={train_loss:.5f}  val_loss={val_loss:.5f}")
```

### 다단계 예측 — Recursive vs Direct

한 스텝 뒤만 예측하는 것을 넘어, 여러 스텝 앞을 예측해야 할 때 두 가지 전략이 있습니다.

```python
"""
Recursive(재귀) 방식:
  예측값을 다음 입력에 다시 넣어 반복 예측
  장점: 모델 하나로 임의 길이 예측 가능 / 단점: 오차가 누적됨 (예측이 예측을 낳음)

Direct(직접) 방식:
  각 미래 스텝마다 별도의 모델(또는 출력 노드)을 훈련
  장점: 오차 누적 없음 / 단점: 예측 스텝 수만큼 모델(또는 출력)이 필요
"""

@torch.no_grad()
def recursive_forecast(model, last_window: np.ndarray, n_steps: int, scaler, device):
    """last_window: 정규화된 마지막 12개월 값, n_steps: 예측할 미래 개월 수"""
    model.eval()
    window = last_window.copy().tolist()
    predictions = []
    for _ in range(n_steps):
        x = torch.tensor(window[-WINDOW_SIZE:], dtype=torch.float32).view(1, WINDOW_SIZE, 1).to(device)
        next_val = model(x).item()
        predictions.append(next_val)
        window.append(next_val)   # 예측값을 다음 입력에 재사용 (재귀)
    return scaler.inverse_transform(np.array(predictions).reshape(-1, 1)).reshape(-1)

future_6months = recursive_forecast(model, X_test[-1], n_steps=6, scaler=scaler, device=device)
print("향후 6개월 CO2 예측(ppm):", np.round(future_6months, 2))
```

```python
# model.py
import numpy as np
import onnxruntime as ort
import joblib

WINDOW_SIZE = 12

class TimeSeriesPredictor:
    def __init__(self, onnx_path: str, scaler_path: str):
        self.session = ort.InferenceSession(onnx_path)
        self.scaler = joblib.load(scaler_path)

    def _scale(self, values: np.ndarray) -> np.ndarray:
        return self.scaler.transform(values.reshape(-1, 1)).reshape(values.shape)

    def _inverse_scale(self, values: np.ndarray) -> np.ndarray:
        return self.scaler.inverse_transform(values.reshape(-1, 1)).reshape(-1)

    def predict(self, recent_values: list[float], n_steps: int) -> list[float]:
        window = self._scale(np.array(recent_values, dtype=np.float32)).tolist()
        preds_scaled = []
        for _ in range(n_steps):
            x = np.array(window[-WINDOW_SIZE:], dtype=np.float32).reshape(1, WINDOW_SIZE, 1)
            out = self.session.run(None, {"input": x})[0]
            next_val = float(out[0, 0])
            preds_scaled.append(next_val)
            window.append(next_val)
        return self._inverse_scale(np.array(preds_scaled)).tolist()

# 서버 시작 시 한 번만 로드
predictor = TimeSeriesPredictor("lstm_co2.onnx", "scaler.pkl")
```

```python
import torch
import torch.nn as nn
from torch.utils.data import Dataset

class TimeSeriesDataset(Dataset):
    def __init__(self, X, y):
        self.X = torch.tensor(X, dtype=torch.float32).unsqueeze(-1)
        self.y = torch.tensor(y, dtype=torch.float32).unsqueeze(-1)

    def __len__(self):
        return len(self.X)

    def __getitem__(self, idx):
        return self.X[idx], self.y[idx]

class LSTMForecaster(nn.Module):
    def __init__(self, input_size=1, hidden_size=64, num_layers=2, dropout=0.2):
        super().__init__()
        self.lstm = nn.LSTM(input_size, hidden_size, num_layers,
                             batch_first=True, dropout=dropout if num_layers > 1 else 0.0)
        self.fc = nn.Linear(hidden_size, 1)

    def forward(self, x):
        lstm_out, _ = self.lstm(x)
        return self.fc(lstm_out[:, -1, :])
```

```python
        optimizer.step()

    model.eval()
    val_loss = 0.0
    with torch.no_grad():
        for xb, yb in val_loader:
            xb, yb = xb.to(device), yb.to(device)
            val_loss += criterion(model(xb), yb).item() * xb.size(0)
    val_loss /= len(val_loader.dataset)

    if val_loss < best_val:
        best_val = val_loss
        torch.save(model.state_dict(), "best_lstm_co2.pt")

    if epoch % 20 == 0:
        print(f"[Epoch {epoch}] val_loss={val_loss:.5f}")

print("훈련 완료 — best_lstm_co2.pt 저장됨")
```

### Step 2. 다변량 슬라이딩 윈도우

4-1절의 `create_sliding_windows`는 1차원 배열(단변량)만 다뤘습니다. 이번에는 각 시점이
**14개 특징을 동시에 가지는 2차원 배열**이므로 윈도우 생성 함수를 다변량용으로 확장합니다.

```python
# lab_jena_step2_windows.py
import numpy as np

WINDOW_SIZE = 24  # 과거 24시간(하루)을 보고 다음 1시간 뒤 기온을 예측

def create_multivariate_windows(data: np.ndarray, target_idx: int, window_size: int):
    """
    data: (전체 시점 수, 특징 수) 형태의 다변량 시계열
    반환: X: (샘플 수, window_size, 특징 수), y: (샘플 수,)  ← y는 target_idx 컬럼의 다음 값
    """
    X, y = [], []
    for i in range(len(data) - window_size):
        X.append(data[i : i + window_size, :])          # 모든 14개 특징을 그대로 입력으로 사용
        y.append(data[i + window_size, target_idx])       # 타깃은 기온 컬럼 하나만
    return np.array(X), np.array(y)

X, y = create_multivariate_windows(values, target_idx, WINDOW_SIZE)
print(X.shape, y.shape)   # (70068, 24, 14) (70068,)   ← input_size가 1이 아니라 14가 됨에 주목
```

### Step 3. 특징별 정규화

다변량 데이터는 특징마다 값의 범위가 크게 다릅니다(기압은 수백 단위, 풍속은 한 자릿수 등).
**각 특징(열)마다 독립적으로** 정규화해야 하며, 이번에도 스케일러는 훈련 구간에만 `fit`합니다.

```python
from sklearn.preprocessing import StandardScaler

n = len(X)
n_train, n_val = int(n * 0.7), int(n * 0.85)

# 스케일러는 (시점, 특징) 2차원 형태로 훈련 구간 원본 시계열에 fit — 윈도우 이전 시점의 raw 값 기준
train_raw = values[:int(len(values) * 0.7)]
scaler = StandardScaler()
scaler.fit(train_raw)   # 14개 컬럼 각각의 평균/표준편차를 개별적으로 학습

def scale_windows(X_windows):
    shape = X_windows.shape                              # (N, window, 14)
    flat = X_windows.reshape(-1, shape[-1])               # (N*window, 14)
    scaled = scaler.transform(flat)
    return scaled.reshape(shape)

X_scaled = scale_windows(X)

# 타깃(y)도 동일한 스케일러의 기온 컬럼 통계로 정규화 (역변환 시 사용)
y_mean, y_std = scaler.mean_[target_idx], scaler.scale_[target_idx]
y_scaled = (y - y_mean) / y_std

X_train, y_train = X_scaled[:n_train], y_scaled[:n_train]
X_val, y_val = X_scaled[n_train:n_val], y_scaled[n_train:n_val]
X_test, y_test = X_scaled[n_val:], y_scaled[n_val:]
print(f"train={len(X_train)}  val={len(X_val)}  test={len(X_test)}")
```

### Step 4. Dataset / 모델 — input_size만 바꿔 재사용

```python
import torch
from torch.utils.data import Dataset, DataLoader

class MultivariateTimeSeriesDataset(Dataset):
    def __init__(self, X, y):
        self.X = torch.tensor(X, dtype=torch.float32)          # 이미 (N, window, 14) 형태 — unsqueeze 불필요
        self.y = torch.tensor(y, dtype=torch.float32).unsqueeze(-1)

    def __len__(self):
        return len(self.X)

    def __getitem__(self, idx):
        return self.X[idx], self.y[idx]

train_loader = DataLoader(MultivariateTimeSeriesDataset(X_train, y_train), batch_size=64, shuffle=True)
val_loader = DataLoader(MultivariateTimeSeriesDataset(X_val, y_val), batch_size=64, shuffle=False)
test_loader = DataLoader(MultivariateTimeSeriesDataset(X_test, y_test), batch_size=64, shuffle=False)

# 4-5절의 LSTMForecaster를 그대로 재사용 — input_size만 14로 지정하면 끝
# (nn.LSTM은 input_size를 생성자 인자로 받으므로 모델 코드 수정이 전혀 필요 없습니다)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = LSTMForecaster(input_size=len(FEATURE_COLUMNS), hidden_size=64, num_layers=2).to(device)

n_params = sum(p.numel() for p in model.parameters())
print(f"총 파라미터 수: {n_params:,}")  # 단변량(CO2) 모델보다 입력 게이트 파라미터가 14배 늘어 소폭 증가
```

### Step 5. 훈련 및 평가 — 4-5, 4-6절 함수 재사용

```python
# train_epoch / eval_epoch 함수는 4-5절에서 정의한 것을 그대로 재사용합니다.
import torch.nn as nn

criterion = nn.MSELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode="min", factor=0.5, patience=3)

best_val_loss = float("inf")
patience, patience_counter = 10, 0

for epoch in range(1, 51):
    train_loss = train_epoch(model, train_loader, optimizer, criterion, device)
    val_loss = eval_epoch(model, val_loader, criterion, device)
    scheduler.step(val_loss)

    if val_loss < best_val_loss:
        best_val_loss = val_loss
        patience_counter = 0
        torch.save(model.state_dict(), "best_lstm_jena.pt")
    else:
        patience_counter += 1
        if patience_counter >= patience:
            print(f"Epoch {epoch}: 조기 종료")
            break

    if epoch % 5 == 0 or epoch == 1:
        print(f"[Epoch {epoch:3d}] train_loss={train_loss:.5f}  val_loss={val_loss:.5f}")

# 4-6절과 동일한 방식으로 정규화를 되돌려 실제 섭씨(°C) 단위 RMSE 계산
model.load_state_dict(torch.load("best_lstm_jena.pt"))
model.eval()
with torch.no_grad():
    X_test_t = torch.tensor(X_test, dtype=torch.float32).to(device)
    pred_scaled = model(X_test_t).cpu().numpy().reshape(-1)

pred_celsius = pred_scaled * y_std + y_mean
true_celsius = y_test * y_std + y_mean

from sklearn.metrics import mean_squared_error
rmse = np.sqrt(mean_squared_error(true_celsius, pred_celsius))
print(f"Jena 기온 예측 RMSE: {rmse:.3f} °C")
```
