# 1. 나만의 리눅스 서버 만들기

> **과정:** 스프링 개발자를 위한 리눅스 기초: 내 애플리케이션을 서버에 배포하기
> **분량:** 8시간
> **실습 환경:** Windows 10/11, VirtualBox 7.x, Rocky Linux 9 Minimal

## 이 장의 학습 목표

이 장을 마치면 다음을 할 수 있습니다.

- 하이퍼바이저의 개념을 이해하고, VirtualBox와 Docker Desktop·WSL2가 충돌하는 이유를 설명할 수 있습니다.
- Windows를 VirtualBox 모드로 전환하고, 전환 결과를 확인할 수 있습니다.
- VirtualBox로 가상 머신을 만들고 Rocky Linux 9을 직접 설치할 수 있습니다.
- 설치한 서버의 운영체제, 네트워크 상태를 점검할 수 있습니다.
- Windows 터미널에서 SSH 키 인증으로 서버에 접속할 수 있습니다.
- 스냅샷, 복제, OVA 내보내기로 서버 이미지를 관리할 수 있습니다.

## 이 장에서 만들 실습 환경

이 장이 끝나면 아래와 같은 환경이 완성됩니다. 이후 모든 장의 실습은 이 서버에서 진행합니다.

```text
┌──────────────────────── Windows PC (호스트) ────────────────────────┐
│                                                                      │
│   Windows 터미널 ── ssh devuser@192.168.56.101 ──┐                   │
│   웹 브라우저   ── http://192.168.56.101:8080 ──┤ (4장 이후)        │
│                                                  │                   │
│   ┌─────────── VirtualBox VM: rocky9-server ─────▼────────────┐     │
│   │  Rocky Linux 9 Minimal (호스트 이름: spring-server)       │     │
│   │                                                           │     │
│   │  enp0s3 : NAT           10.0.2.15       → 인터넷 연결     │     │
│   │  enp0s8 : 호스트 전용   192.168.56.101  → Windows와 통신  │     │
│   └───────────────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────────────────┘
```

| 항목 | 값 |
|---|---|
| VM 이름 | `rocky9-server` |
| 호스트 이름 | `spring-server` |
| 일반 사용자 | `devuser` (관리자 권한) |
| 메모리 / CPU / 디스크 | 4GB / 2코어 / 30GB (동적 할당) |
| 네트워크 어댑터 1 | NAT |
| 네트워크 어댑터 2 | 호스트 전용 어댑터 |

> **참고:** IP 주소 `192.168.56.101`은 VirtualBox 기본 설정에서 처음 할당되는 주소입니다. 환경에 따라 다를 수 있으니, 1.4절에서 확인한 실제 주소를 사용하십시오.

## 1.1 가상화의 이해와 VirtualBox 모드 전환

### 1.1.1 왜 가상 머신을 사용하는가

스프링 애플리케이션을 배포할 서버는 보통 리눅스입니다. 하지만 수업을 위해 학습자마다 실제 서버 컴퓨터를 한 대씩 준비할 수는 없습니다. **가상 머신(Virtual Machine, VM)**은 내 PC 안에 소프트웨어로 만든 또 하나의 컴퓨터입니다. VM을 사용하면 다음과 같은 장점이 있습니다.

- 내 Windows 환경을 건드리지 않고 리눅스 서버를 마음껏 실험할 수 있습니다.
- 설정을 망가뜨려도 스냅샷으로 몇 초 만에 되돌릴 수 있습니다.
- 서버 전체를 파일 하나(OVA)로 만들어 다른 PC로 옮길 수 있습니다.

### 1.1.2 하이퍼바이저란 무엇인가

**하이퍼바이저(Hypervisor)**는 하나의 실제 컴퓨터에서 여러 VM이 CPU, 메모리, 디스크를 나누어 쓰도록 관리하는 소프트웨어입니다. 하이퍼바이저는 크게 두 가지로 나뉩니다.

| 구분 | 동작 방식 | 예 |
|---|---|---|
| Type 1 (네이티브) | 하드웨어 위에서 직접 동작하며, 운영체제도 그 위에서 실행됩니다 | Hyper-V, VMware ESXi, KVM |
| Type 2 (호스트형) | Windows 같은 운영체제 위에서 하나의 프로그램으로 동작합니다 | VirtualBox, VMware Workstation |

우리 PC에 설치된 도구들은 다음과 같은 관계에 있습니다.

| 도구 | 사용하는 가상화 기술 |
|---|---|
| WSL2 | Hyper-V 기반의 경량 VM에서 리눅스 커널을 실행합니다 |
| Docker Desktop (Windows) | WSL2 위에서 Docker 엔진을 실행합니다 |
| VirtualBox | CPU의 가상화 기능(Intel VT-x, AMD-V)을 직접 사용하려고 합니다 |

### 1.1.3 왜 충돌이 생기는가

CPU의 가상화 기능은 **한 번에 하나의 하이퍼바이저만 직접 사용할 수 있습니다.** WSL2나 Docker Desktop 때문에 Windows의 하이퍼바이저(Hyper-V)가 켜져 있으면, Windows 자신도 Hyper-V 위에서 동작하게 되고 VirtualBox는 CPU 가상화 기능을 직접 쓸 수 없습니다.

```text
[하이퍼바이저가 켜진 상태]              [하이퍼바이저가 꺼진 상태]

 Windows   WSL2/Docker   VirtualBox      Windows        VirtualBox
    │          │             │              │              │
    └──── Hyper-V ───────────┘              │         VT-x / AMD-V
              │                             │              │
           하드웨어                       하드웨어 ────────┘
```

VirtualBox 7.x는 이 상태에서도 Hyper-V를 거쳐 VM을 실행할 수 있지만, 속도가 크게 느려지고 일부 기능이 불안정합니다. 이때 VirtualBox 화면 아래 상태 표시줄에 **초록색 거북이 아이콘**이 나타납니다.

그래서 이 과정에서는 두 가지 모드를 오가며 사용합니다.

| 모드 | 하이퍼바이저 | 사용할 수 있는 도구 | 사용 시기 |
|---|---|---|---|
| VirtualBox 모드 | 꺼짐 | VirtualBox | 과정 기간 |
| Docker 모드 | 켜짐 | Docker Desktop, WSL2 | 과정 종료 후 (5.8절) |

이 방법은 Docker Desktop이나 WSL2를 **삭제하지 않습니다.** 하이퍼바이저의 실행 여부만 바꾸므로, 설치된 배포판과 컨테이너 이미지는 그대로 남아 있습니다.

### 1.1.4 실습: VirtualBox 모드로 전환하기

> **시작하기 전에:** 부팅 설정을 바꾸면 BitLocker가 켜진 PC에서 복구 키를 요구할 수 있습니다. 복구 키를 미리 확인해 두십시오. 기관에서 관리하는 PC라면 담당자의 안내를 따르십시오.

**1단계. Docker Desktop 종료 및 자동 실행 해제**

1. Docker Desktop을 열고 **Settings → General**에서 **Start Docker Desktop when you sign in** 항목의 체크를 해제합니다.
2. 작업 표시줄 오른쪽 트레이의 Docker 아이콘을 마우스 오른쪽 버튼으로 클릭하고 **Quit Docker Desktop**을 선택합니다.

**2단계. WSL2 종료**

PowerShell을 열고 다음 명령을 실행합니다.

```powershell
wsl --shutdown
wsl --list --verbose
```

모든 배포판의 `STATE`가 `Stopped`이면 정상입니다.

```text
  NAME              STATE           VERSION
* Ubuntu            Stopped         2
  docker-desktop    Stopped         2
```

**3단계. Windows 하이퍼바이저 비활성화**

시작 메뉴에서 PowerShell을 마우스 오른쪽 버튼으로 클릭하고 **관리자 권한으로 실행**을 선택한 뒤 다음 명령을 실행합니다.

```powershell
bcdedit /set hypervisorlaunchtype off
```

`작업을 완료했습니다.`라는 메시지가 나오면 성공입니다.

**4단계. 재부팅**

설정은 재부팅해야 적용됩니다. 열려 있는 작업을 저장하고 PC를 다시 시작합니다.

**5단계. 전환 결과 확인**

재부팅 후 PowerShell에서 다음 명령을 실행합니다.

```powershell
systeminfo | findstr /i "Hyper-V"
```

| 결과 | 의미 |
|---|---|
| `하이퍼바이저가 검색되었습니다` (영문: `A hypervisor has been detected`) | 하이퍼바이저가 **아직 켜져 있습니다** |
| `VM 모니터 모드 확장: 예` 등 Hyper-V 요구 사항 목록이 표시됨 | 하이퍼바이저가 **꺼져 있습니다** (정상) |

**6단계. 여전히 하이퍼바이저가 감지될 때**

Windows의 보안 기능 중 일부는 하이퍼바이저가 필요하기 때문에, 이 기능이 켜져 있으면 3단계 설정이 적용되지 않을 수 있습니다.

1. **Windows 보안 → 장치 보안 → 코어 격리 세부 정보**로 이동합니다.
2. **메모리 무결성**이 켜져 있으면 끄고 재부팅합니다.
3. 과정이 끝나면 5.8절에서 다시 켭니다.

> **체크포인트 1.1:** `systeminfo` 결과에 "하이퍼바이저가 검색되었습니다"라는 문구가 나오지 않습니다.

## 1.2 VirtualBox 설치와 VM 만들기

### 1.2.1 VirtualBox 설치

1. 강의장 공유 폴더에서 VirtualBox 설치 파일을 실행합니다. (공식 배포처: https://www.virtualbox.org)
2. 설치 중 **네트워크 인터페이스가 잠시 끊어질 수 있다는 경고**가 나오면 **예**를 선택합니다. VirtualBox가 호스트 전용 네트워크용 가상 어댑터를 설치하는 과정입니다.
3. Python 관련 의존성 경고가 나오면 그대로 진행해도 됩니다. 이 과정에서는 사용하지 않습니다.
4. 설치가 끝나면 VirtualBox 관리자를 실행합니다.

### 1.2.2 호스트 전용 네트워크 확인

VM과 Windows가 서로 통신할 전용 네트워크가 준비되어 있는지 확인합니다.

1. VirtualBox 관리자에서 **파일 → 도구 → 네트워크 관리자**를 엽니다. (버전에 따라 **Tools → Network** 메뉴에 있습니다.)
2. **Host-only Networks** 탭에 `VirtualBox Host-Only Ethernet Adapter`가 있는지 확인합니다.
3. 설정값이 다음과 같은지 확인합니다.

| 항목 | 기본값 |
|---|---|
| IPv4 주소 | `192.168.56.1` (Windows 쪽 주소) |
| 서브넷 마스크 | `255.255.255.0` |
| DHCP 서버 | 사용함 (`192.168.56.100`, 할당 범위 `101 ~ 254`) |

어댑터가 없다면 **만들기** 버튼으로 새로 만듭니다.

### 1.2.3 새 VM 만들기

1. VirtualBox 관리자에서 **새로 만들기**를 클릭합니다.
2. 다음과 같이 입력합니다.

| 항목 | 입력값 | 설명 |
|---|---|---|
| 이름 | `rocky9-server` | VirtualBox에서 VM을 구분하는 이름입니다 |
| 폴더 | 기본값 | 디스크 여유 공간이 충분한 드라이브인지 확인합니다 |
| ISO 이미지 | **비워 둡니다** | 아래 설명 참고 |
| 종류 | Linux | |
| 버전 | Red Hat (64-bit) | Rocky Linux는 Red Hat Enterprise Linux와 호환되는 배포판입니다 |

> **ISO 이미지를 비워 두는 이유:** 이 화면에서 ISO를 지정하면 VirtualBox가 **무인 설치(Unattended Installation)**를 진행하려고 할 수 있습니다. 무인 설치는 편리하지만 설치 과정을 하나도 볼 수 없습니다. 이 장의 목표는 설치 화면 하나하나를 이해하는 것이므로, ISO는 VM을 만든 뒤 따로 연결합니다.

3. 하드웨어를 설정합니다.

| 항목 | 값 | 설명 |
|---|---|---|
| 기본 메모리 | 4096MB | Spring Boot, MySQL, Nginx를 함께 실행하기 위한 크기입니다 |
| 프로세서 | 2 | |
| EFI 사용 | 체크 해제 | 기본값(BIOS 방식)을 그대로 사용합니다 |

4. 가상 하드 디스크를 설정합니다.

| 항목 | 값 | 설명 |
|---|---|---|
| 디스크 크기 | 30GB | |
| 형식 | VDI | VirtualBox 기본 형식입니다 |
| 미리 전체 크기 할당 | 체크 해제 | **동적 할당**: 실제로 사용한 만큼만 PC 디스크를 차지합니다 |

5. **완료**를 클릭합니다.

### 1.2.4 VM 세부 설정

VM 목록에서 `rocky9-server`를 선택하고 **설정**을 클릭합니다.

**저장소: ISO 연결**

1. **저장소** 메뉴에서 컨트롤러 아래의 **비어 있음**(광학 드라이브)을 선택합니다.
2. 오른쪽의 디스크 아이콘을 클릭하고 **디스크 파일 선택**을 누릅니다.
3. 강의장 공유 폴더의 `Rocky-9.x-x86_64-minimal.iso` 파일을 선택합니다.

**네트워크: 어댑터 2개 구성**

| 탭 | 설정 |
|---|---|
| 어댑터 1 | 네트워크 어댑터 사용 체크, 다음에 연결됨: **NAT** |
| 어댑터 2 | 네트워크 어댑터 사용 체크, 다음에 연결됨: **호스트 전용 어댑터**, 이름: `VirtualBox Host-Only Ethernet Adapter` |

**두 어댑터를 쓰는 이유**

| 어댑터 | 역할 | 비유 |
|---|---|---|
| NAT | VM이 Windows의 인터넷 연결을 빌려 외부로 나갑니다. `dnf`로 패키지를 내려받을 때 필요합니다. 외부에서 VM으로 직접 들어올 수는 없습니다 | 공유기 뒤에 있는 집 PC |
| 호스트 전용 | Windows와 VM만 연결된 사설 네트워크입니다. SSH 접속, 브라우저로 Spring 앱 확인에 사용합니다 | Windows와 VM 사이에 꽂은 랜선 한 가닥 |

**시스템: 부팅 순서 확인**

**시스템 → 마더보드**의 부팅 순서에서 **광학**이 **하드 디스크**보다 위에 있는지 확인합니다. 처음에는 디스크가 비어 있으므로 ISO로 부팅됩니다.

**확인**을 클릭해 설정을 저장합니다.

> **체크포인트 1.2:** VM 설정 화면에서 ISO 파일이 연결되어 있고, 네트워크 어댑터 1은 NAT, 어댑터 2는 호스트 전용 어댑터로 설정되어 있습니다.

## 1.3 Rocky Linux 9 설치

### 1.3.1 왜 Rocky Linux인가

리눅스 배포판은 크게 두 계열로 나뉩니다.

| 계열 | 대표 배포판 | 패키지 관리 도구 | 주 사용처 |
|---|---|---|---|
| RHEL 계열 | Red Hat Enterprise Linux, **Rocky Linux**, AlmaLinux, Amazon Linux | `dnf` (예전에는 `yum`) | 기업 서버, 금융·공공 기관, AWS |
| Debian 계열 | Debian, Ubuntu | `apt` | 개발 환경, 스타트업, 클라우드 |

Rocky Linux는 RHEL과 호환되는 무료 배포판입니다. 여기서 익힌 명령어와 설정 방법은 AWS의 Amazon Linux 2023, 기업의 RHEL 서버에서도 거의 그대로 통합니다.

### 1.3.2 설치 프로그램 시작

1. VM을 선택하고 **시작**을 클릭합니다.
2. 부팅 메뉴가 나타나면 방향키로 **Install Rocky Linux 9.x**를 선택하고 Enter 키를 누릅니다. (아무 키도 누르지 않으면 설치 매체 검사를 먼저 진행하므로 시간이 더 걸립니다.)
3. 그래픽 설치 프로그램(**Anaconda**)이 시작됩니다.

> **마우스가 VM 창에서 빠져나오지 않을 때:** 오른쪽 `Ctrl` 키(호스트 키)를 누르면 마우스가 Windows로 돌아옵니다.

### 1.3.3 언어 선택

**English (United States)**를 선택할 것을 권장합니다.

- 오류 메시지를 그대로 검색했을 때 훨씬 많은 자료를 찾을 수 있습니다.
- 실무 서버도 대부분 영어 환경으로 운영합니다.

### 1.3.4 설치 요약(Installation Summary) 화면

모든 설정은 이 화면에서 항목을 하나씩 눌러 진행합니다. 경고 표시(주황색 아이콘)가 있는 항목은 반드시 설정해야 합니다.

**① Keyboard**

- **English (US)**를 그대로 둡니다. 한국어 키보드 배열을 추가하면 특수 문자 위치가 달라져 비밀번호 입력 오류가 생길 수 있습니다.

**② Time & Date**

- 지도에서 **Asia / Seoul**을 선택합니다.
- **Network Time**이 켜져 있는지 확인합니다. (네트워크를 켠 뒤에 활성화됩니다.)
- 서버 시간이 정확해야 로그의 시간과 Spring 애플리케이션의 시간 처리가 맞습니다.

**③ Software Selection**

- **Minimal Install**을 선택합니다.

| 선택지 | 특징 |
|---|---|
| Server with GUI | 데스크톱 화면이 포함됩니다. 메모리와 디스크를 많이 쓰고, 공격받을 수 있는 지점이 늘어납니다 |
| **Minimal Install** | 꼭 필요한 패키지만 설치합니다. 나머지는 필요할 때 `dnf`로 추가합니다 |

실제 서버는 화면 없이 원격으로 관리하므로 GUI가 필요 없습니다.

**④ Installation Destination**

1. `30 GiB` 디스크가 선택(체크 표시)되어 있는지 확인합니다.
2. **Storage Configuration**은 **Automatic**을 그대로 둡니다.
3. 왼쪽 위의 **Done**을 클릭합니다.

자동 구성은 디스크를 다음과 같이 나눕니다. (디스크 크기에 따라 `/home`이 따로 만들어지기도 합니다.)

| 영역 | 역할 |
|---|---|
| `/boot` | 리눅스 커널과 부팅에 필요한 파일을 보관합니다 |
| `/` (root) | 운영체제와 모든 파일이 저장되는 최상위 영역입니다 |
| swap | 메모리가 부족할 때 디스크를 메모리처럼 사용하는 영역입니다 |

`/`와 swap은 **LVM(논리 볼륨 관리자)** 위에 만들어집니다. LVM을 사용하면 나중에 디스크를 추가해 용량을 늘리기 쉽습니다.

**⑤ KDUMP**

- 커널이 비정상 종료될 때 메모리 내용을 저장하는 기능입니다. 메모리를 따로 예약하므로, 실습용 VM에서는 **Enable kdump**의 체크를 해제합니다.

**⑥ Network & Host Name**

이 항목을 빠뜨리면 설치 후 인터넷과 SSH를 사용할 수 없으니 반드시 설정합니다.

1. 목록에 이더넷 장치 2개가 보입니다.

| 장치 이름 | VirtualBox 어댑터 |
|---|---|
| `enp0s3` | 어댑터 1 (NAT) |
| `enp0s8` | 어댑터 2 (호스트 전용) |

2. 각 장치를 선택하고 오른쪽 위의 스위치를 **ON**으로 바꿉니다. IP 주소가 표시되면 정상입니다.
3. 아래쪽 **Host Name**에 `spring-server`를 입력하고 **Apply**를 클릭합니다.

> **장치 이름의 의미:** `en`은 이더넷, `p0`는 PCI 버스 0번, `s3`은 슬롯 3번을 뜻합니다. 예전 리눅스의 `eth0`, `eth1` 같은 이름 대신, 하드웨어 위치에 따라 이름이 정해지므로 재부팅해도 바뀌지 않습니다.

**⑦ Root Password**

1. root 비밀번호를 입력합니다. 실습용이라도 8자 이상으로 정합니다.
2. **Lock root account**가 체크되어 있다면 해제합니다. (실습 중 문제 해결을 위해 root 로그인을 열어 둡니다.)
3. **Allow root SSH login with password**는 체크하지 **않습니다.** 원격에서 root로 바로 로그인하는 것은 보안상 위험합니다.

**⑧ User Creation**

| 항목 | 입력값 |
|---|---|
| Full name | Dev User |
| User name | `devuser` |
| Make this user administrator | **체크** |
| Password | 기억하기 쉬운 비밀번호 |

**Make this user administrator**를 체크하면 사용자가 `wheel` 그룹에 들어가 `sudo` 명령으로 관리자 작업을 할 수 있습니다. 실무에서도 root로 직접 작업하지 않고, 일반 사용자로 로그인한 뒤 필요할 때만 `sudo`를 사용합니다.

### 1.3.5 설치 진행과 재부팅

1. 모든 항목의 경고 표시가 사라지면 **Begin Installation**을 클릭합니다.
2. 설치는 PC 성능에 따라 5~15분 정도 걸립니다. 기다리는 동안 1.3.4절의 표를 다시 읽어 봅니다.
3. **Reboot System** 버튼이 나타나면, 누르기 전에 ISO를 분리합니다.
   - VM 창 메뉴의 **장치 → 광학 드라이브 → 가상 드라이브에서 디스크 꺼내기**를 선택합니다.
   - ISO를 분리하지 않으면 재부팅 후 다시 설치 화면으로 들어갈 수 있습니다.
4. **Reboot System**을 클릭합니다.

> **체크포인트 1.3:** 재부팅 후 검은 화면에 `spring-server login:` 프롬프트가 나타납니다.

## 1.4 첫 로그인과 기본 점검

### 1.4.1 로그인

```text
spring-server login: devuser
Password:
```

비밀번호를 입력할 때는 화면에 아무것도 표시되지 않습니다. 입력이 안 되는 것이 아니라, 옆 사람이 비밀번호 길이를 알 수 없도록 숨기는 것입니다.

로그인에 성공하면 다음과 같은 **프롬프트**가 나타납니다.

```text
[devuser@spring-server ~]$
```

| 부분 | 의미 |
|---|---|
| `devuser` | 현재 로그인한 사용자 |
| `spring-server` | 서버의 호스트 이름 |
| `~` | 현재 위치한 디렉터리 (`~`는 내 홈 디렉터리 `/home/devuser`) |
| `$` | 일반 사용자라는 표시 (root는 `#`) |

### 1.4.2 root와 일반 사용자

| 구분 | root | 일반 사용자 (`devuser`) |
|---|---|---|
| 권한 | 시스템의 모든 것을 바꿀 수 있습니다 | 자기 홈 디렉터리 안에서만 자유롭습니다 |
| 프롬프트 | `#` | `$` |
| 관리자 작업 | 바로 실행 | 명령 앞에 `sudo`를 붙여 실행 |

`sudo`를 사용하면 누가 언제 어떤 관리자 명령을 실행했는지 기록이 남습니다. 또 실수로 시스템 파일을 지우는 일도 줄일 수 있습니다.

```bash
whoami          # 현재 사용자 확인
sudo whoami     # sudo로 실행하면 root로 표시됩니다 (처음에는 비밀번호를 묻습니다)
```

### 1.4.3 시스템 정보 확인

```bash
cat /etc/os-release
```

```text
NAME="Rocky Linux"
VERSION="9.x (Blue Onyx)"
ID="rocky"
ID_LIKE="rhel centos fedora"
...
```

`ID_LIKE` 항목을 보면 이 배포판이 RHEL, CentOS, Fedora와 같은 계열이라는 것을 알 수 있습니다.

```bash
hostnamectl     # 호스트 이름, 운영체제, 커널, 가상화 종류
uname -r        # 커널 버전만 확인
```

`hostnamectl` 결과의 `Virtualization: oracle` 항목은 이 서버가 VirtualBox(Oracle) VM이라는 뜻입니다.

### 1.4.4 네트워크 확인

```bash
ip addr
```

```text
1: lo: <LOOPBACK,UP,LOWER_UP> ...
    inet 127.0.0.1/8 scope host lo
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    inet 10.0.2.15/24 ... enp0s3
3: enp0s8: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    inet 192.168.56.101/24 ... enp0s8
```

| 인터페이스 | 주소 | 의미 |
|---|---|---|
| `lo` | `127.0.0.1` | 자기 자신을 가리키는 주소(localhost) |
| `enp0s3` | `10.0.2.15` | NAT 네트워크 주소. 인터넷으로 나갈 때 사용합니다 |
| `enp0s8` | `192.168.56.101` | 호스트 전용 네트워크 주소. **이 주소를 기록해 두십시오** |

연결 상태를 확인합니다.

```bash
ping -c 4 8.8.8.8           # 인터넷 연결 확인 (IP 주소로)
ping -c 4 rockylinux.org    # 도메인 이름 해석(DNS)까지 확인
ping -c 4 192.168.56.1      # Windows(호스트)와의 연결 확인
```

`-c 4`는 4번만 보내고 멈추라는 옵션입니다. 이 옵션 없이 실행했다면 `Ctrl + C`로 멈춥니다.

> **참고:** Windows 방화벽 설정에 따라 `192.168.56.1`로의 `ping`이 응답하지 않을 수 있습니다. 이 경우 1.5절에서 Windows → VM 방향의 SSH 접속이 되는지로 확인합니다.

### 1.4.5 첫 업데이트

설치 ISO가 만들어진 뒤에 나온 보안 패치를 적용합니다.

```bash
sudo dnf update -y
```

| 부분 | 의미 |
|---|---|
| `sudo` | 관리자 권한으로 실행 |
| `dnf` | RHEL 계열의 패키지 관리 도구 |
| `update` | 설치된 모든 패키지를 최신 버전으로 업데이트 |
| `-y` | "계속하시겠습니까?" 질문에 자동으로 yes |

커널이 업데이트되었다면 재부팅해야 새 커널이 적용됩니다.

### 1.4.6 안전한 종료와 재시작

서버는 전원 버튼을 누르듯 끄면 안 됩니다. 실행 중인 서비스가 데이터를 저장할 시간을 주어야 합니다.

```bash
sudo reboot                 # 지금 재시작
sudo shutdown -r +5         # 5분 뒤 재시작 (접속자에게 알림이 전송됩니다)
sudo shutdown -c            # 예약한 종료 취소
sudo poweroff               # 지금 종료
```

> **주의:** VirtualBox 창의 X 버튼을 누르고 **전원 끄기**를 선택하는 것은 컴퓨터의 전원 코드를 뽑는 것과 같습니다. 꼭 필요한 경우가 아니라면 **ACPI 종료 신호 보내기**를 선택하거나 VM 안에서 `poweroff`를 실행하십시오.

> **체크포인트 1.4:** `ip addr`로 `enp0s8`의 IP 주소를 확인했고, `sudo dnf update -y`가 오류 없이 끝났습니다.

## 1.5 SSH로 원격 접속하기

### 1.5.1 콘솔 대신 SSH를 쓰는 이유

지금까지는 VirtualBox 창(콘솔)에서 직접 명령을 입력했습니다. 하지만 실제 서버는 데이터센터나 클라우드에 있으므로 모니터를 연결할 수 없습니다. **SSH(Secure Shell)**는 네트워크를 통해 다른 컴퓨터에 암호화된 연결로 접속하는 방법입니다.

SSH를 사용하면 다음과 같은 장점도 있습니다.

- 익숙한 Windows 터미널에서 복사·붙여넣기를 자유롭게 할 수 있습니다.
- 여러 창을 열어 한쪽에서는 로그를 보고, 다른 쪽에서는 명령을 실행할 수 있습니다.
- 4장에서 `scp`로 jar 파일을 서버에 전송할 때도 같은 연결 방식을 사용합니다.

Rocky Linux에는 SSH 서버(`sshd`)가 이미 설치되어 실행 중입니다.

```bash
systemctl status sshd       # active (running)이면 정상, q 키로 빠져나옵니다
```

### 1.5.2 Windows에서 비밀번호로 접속하기

Windows 10/11에는 SSH 클라이언트가 기본으로 들어 있습니다. **Windows 터미널**(또는 PowerShell)을 열고 다음과 같이 입력합니다.

```powershell
ssh devuser@192.168.56.101
```

처음 접속할 때는 다음과 같은 질문이 나옵니다.

```text
The authenticity of host '192.168.56.101' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

이 메시지는 "이 서버를 처음 보는데, 정말 접속하려는 서버가 맞습니까?"라는 확인입니다. `yes`를 입력하면 서버의 지문이 `C:\Users\<사용자>\.ssh\known_hosts`에 저장되고, 다음부터는 묻지 않습니다. 비밀번호를 입력하면 접속됩니다.

```text
[devuser@spring-server ~]$
```

접속을 끝낼 때는 `exit`를 입력합니다.

### 1.5.3 키 기반 인증 설정하기

비밀번호 방식은 입력이 번거롭고, 비밀번호를 무작위로 대입하는 공격에 취약합니다. 실무 서버와 AWS EC2는 **키 기반 인증**을 기본으로 사용합니다.

| 키 | 보관 위치 | 비유 |
|---|---|---|
| 개인 키 (`id_ed25519`) | 내 PC에만 보관, **절대 공유하지 않음** | 열쇠 |
| 공개 키 (`id_ed25519.pub`) | 접속할 서버에 등록 | 자물쇠 |

서버에 자물쇠(공개 키)를 달아 두면, 그에 맞는 열쇠(개인 키)를 가진 PC만 접속할 수 있습니다.

**1단계. Windows에서 키 만들기**

```powershell
ssh-keygen -t ed25519
```

- 저장 위치를 물으면 Enter 키를 눌러 기본값을 사용합니다.
- 암호(passphrase)를 물으면 실습에서는 Enter 키를 두 번 눌러 비워 둡니다. 실무에서는 개인 키를 도난당해도 바로 쓸 수 없도록 암호를 설정하는 것이 좋습니다.

```powershell
dir $env:USERPROFILE\.ssh
```

`id_ed25519`(개인 키)와 `id_ed25519.pub`(공개 키) 두 파일이 만들어졌는지 확인합니다.

**2단계. 공개 키를 서버에 등록하기**

리눅스와 macOS에는 `ssh-copy-id`라는 명령이 있지만 Windows에는 없습니다. 다음 명령으로 같은 작업을 합니다. (한 줄로 입력합니다.)

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh devuser@192.168.56.101 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

이 명령은 다음 순서로 동작합니다.

1. Windows에서 공개 키 파일의 내용을 읽습니다.
2. SSH로 서버에 접속합니다(이번에는 비밀번호를 입력합니다).
3. 서버에 `~/.ssh` 디렉터리를 만들고 권한을 `700`(나만 접근)으로 설정합니다.
4. 공개 키를 `~/.ssh/authorized_keys` 파일 끝에 추가하고 권한을 `600`(나만 읽기·쓰기)으로 설정합니다.

권한 숫자의 의미는 3.2절에서 자세히 배웁니다. 지금은 **SSH가 이 파일들의 권한이 느슨하면 보안을 위해 키 인증을 거부한다**는 점만 기억하십시오.

**3단계. 키로 접속 확인**

```powershell
ssh devuser@192.168.56.101
```

비밀번호를 묻지 않고 바로 접속되면 성공입니다.

### 1.5.4 SSH 설정 파일로 접속 간단하게 만들기

매번 IP 주소를 입력하는 대신 별칭을 만들어 둡니다. Windows에서 `C:\Users\<사용자>\.ssh\config` 파일을 메모장으로 만들고 다음 내용을 저장합니다. (파일 이름에 `.txt` 확장자가 붙지 않도록 주의합니다.)

```text
Host spring
    HostName 192.168.56.101
    User devuser
    IdentityFile ~/.ssh/id_ed25519
```

이제 다음 명령만으로 접속할 수 있습니다.

```powershell
ssh spring
```

### 1.5.5 VM을 화면 없이 실행하기(헤드리스 시작)

SSH로 접속할 수 있게 되었으니 VirtualBox 콘솔 창은 더 이상 필요 없습니다. 실제 서버처럼 화면 없이 VM을 실행해 봅니다.

**VirtualBox 관리자에서**

1. VM을 종료합니다(`sudo poweroff`).
2. **시작** 버튼 옆의 화살표를 클릭하고 **헤드리스 시작**을 선택합니다.
3. 30초 정도 기다린 뒤 `ssh spring`으로 접속합니다.

**명령어로**

VirtualBox에는 `VBoxManage`라는 명령줄 도구가 있습니다. PowerShell에서 실행합니다.

```powershell
cd "C:\Program Files\Oracle\VirtualBox"
.\VBoxManage list vms                                         # VM 목록
.\VBoxManage startvm "rocky9-server" --type headless          # 헤드리스로 시작
.\VBoxManage list runningvms                                  # 실행 중인 VM
.\VBoxManage controlvm "rocky9-server" acpipowerbutton        # 정상 종료 신호 보내기
```

> **체크포인트 1.5:** 헤드리스로 시작한 VM에 `ssh spring` 명령으로 비밀번호 없이 접속됩니다.

## 1.6 스냅샷과 이미지 관리

### 1.6.1 스냅샷이란

**스냅샷(Snapshot)**은 특정 시점의 VM 상태(디스크, 설정, 실행 중이었다면 메모리까지)를 저장해 두는 기능입니다. 게임의 세이브 포인트와 같습니다. 이 과정에서는 다음과 같은 시점마다 스냅샷을 만들 것을 권장합니다.

| 시점 | 스냅샷 이름 예 |
|---|---|
| 1장 완료 | `01-설치-완료` |
| 3장 완료 | `03-Java-설치-완료` |
| 4장 완료 | `04-서비스-등록-완료` |
| 위험한 실습 직전 | `before-selinux` 등 |

> **주의:** 스냅샷은 백업이 아닙니다. 스냅샷은 원본 디스크에 의존하므로, 원본 디스크 파일이 손상되면 스냅샷도 함께 사용할 수 없습니다. 다른 PC로 옮기거나 보관하려면 1.6.4절의 OVA 내보내기를 사용합니다.

### 1.6.2 실습: 스냅샷 만들기

1. VM을 종료합니다. (실행 중에도 만들 수 있지만, 종료 상태가 가장 깔끔합니다.)
2. VirtualBox 관리자에서 VM 이름 오른쪽의 메뉴 아이콘을 클릭하고 **스냅샷**을 선택합니다.
3. **찍기**를 클릭하고 이름을 `01-설치-완료`로 입력합니다. 설명란에는 "Rocky Linux 9 최소 설치, dnf update, SSH 키 인증 설정"처럼 상태를 적어 둡니다.

명령어로도 만들 수 있습니다.

```powershell
.\VBoxManage snapshot "rocky9-server" take "01-설치-완료" --description "최소 설치, SSH 키 인증"
.\VBoxManage snapshot "rocky9-server" list
```

### 1.6.3 실습: 일부러 망가뜨리고 되돌리기

스냅샷이 있으면 어떤 실수도 되돌릴 수 있다는 것을 직접 확인해 봅니다.

1. VM을 시작하고 SSH로 접속합니다.
2. SSH 키 등록 파일을 삭제합니다.

```bash
rm ~/.ssh/authorized_keys
exit
```

3. 다시 접속해 봅니다.

```powershell
ssh spring
```

이제 비밀번호를 묻습니다. 키 인증이 망가진 것입니다.

4. VM을 종료하고, 스냅샷 화면에서 `01-설치-완료`를 선택한 뒤 **복원**을 클릭합니다. "현재 상태의 스냅샷을 만들겠습니까?"라는 질문에는 체크를 해제하고 복원합니다.
5. VM을 시작하고 `ssh spring`으로 접속하면 다시 비밀번호 없이 접속됩니다.

### 1.6.4 VM 복제

같은 구성의 서버가 하나 더 필요할 때(예: 웹 서버와 DB 서버를 나눌 때) **복제**를 사용합니다.

| 복제 방식 | 특징 |
|---|---|
| 완전한 복제 | 디스크 전체를 복사합니다. 원본과 완전히 독립적이지만 디스크 공간을 많이 씁니다 |
| 연결된 복제 | 원본 디스크를 공유하고 바뀐 부분만 저장합니다. 빠르고 공간을 적게 쓰지만 원본이 있어야 동작합니다 |

복제할 때는 **MAC 주소 정책**에서 **모든 네트워크 어댑터의 새 MAC 주소 생성**을 선택해야 합니다. MAC 주소가 같으면 두 VM이 같은 IP를 받아 네트워크 충돌이 생깁니다.

복제한 VM은 호스트 이름도 원본과 같으므로, 접속한 뒤 바꿔 줍니다.

```bash
sudo hostnamectl set-hostname spring-server-2
```

### 1.6.5 OVA 내보내기와 가져오기

**OVA(Open Virtual Appliance)**는 VM의 설정과 디스크를 파일 하나로 묶은 표준 형식입니다. VMware 같은 다른 가상화 프로그램에서도 열 수 있습니다.

**내보내기**

1. VM을 종료합니다.
2. **파일 → 가상 시스템 내보내기**를 선택합니다.
3. `rocky9-server`를 선택하고, 형식은 **OVF 2.0**, 파일 이름은 `rocky9-server-ch01.ova`로 지정합니다.
4. **MAC 주소 정책**은 **NAT 네트워크 어댑터의 MAC 주소만 포함**을 선택합니다.
5. **내보내기**를 클릭합니다.

**가져오기**

1. **파일 → 가상 시스템 가져오기**를 선택하고 OVA 파일을 지정합니다.
2. **MAC 주소 정책**은 **모든 네트워크 어댑터의 새 MAC 주소 생성**을 선택합니다.
3. 가져온 VM의 호스트 전용 어댑터 IP가 원본과 다를 수 있으므로, 접속 전에 콘솔에서 `ip addr`로 확인합니다.

> **진도가 늦어졌을 때:** 설치를 끝내지 못한 학습자는 강사가 제공하는 `rocky9-server-ch01.ova`를 가져와서 2장을 시작할 수 있습니다. 이 경우 1.5.3절의 키 등록 과정은 직접 다시 진행해야 합니다. 강사의 공개 키가 아닌 **내 PC의 공개 키**를 등록해야 하기 때문입니다.

> **체크포인트 1.6:** 스냅샷 목록에 `01-설치-완료`가 있고, 스냅샷 복원으로 망가뜨린 설정을 되돌려 보았습니다.

## 1.7 설치 문제 해결

설치 과정에서 자주 만나는 문제와 해결 방법입니다. 문제를 만나면 **증상 → 원인 추측 → 확인 → 해결** 순서로 생각해 봅시다. 이 습관은 이후 모든 장의 장애 대응 실습에서도 그대로 사용합니다.

### 문제 1. VM이 시작되지 않고 "VT-x is not available" 또는 "AMD-V is disabled" 오류가 납니다

| 원인 | 해결 |
|---|---|
| BIOS/UEFI에서 CPU 가상화 기능이 꺼져 있습니다 | PC를 재부팅하며 BIOS 설정 화면으로 들어가 Intel Virtualization Technology(VT-x) 또는 SVM Mode(AMD-V)를 Enabled로 바꿉니다 |
| 하이퍼바이저가 아직 가상화 기능을 차지하고 있습니다 | 1.1.4절의 3~6단계를 다시 확인합니다 |

Windows에서 가상화 기능이 켜져 있는지는 **작업 관리자 → 성능 → CPU**의 **가상화: 사용**으로 확인할 수 있습니다.

### 문제 2. VM이 매우 느리고, 상태 표시줄에 거북이 아이콘이 보입니다

VirtualBox가 Hyper-V를 거쳐 실행되고 있다는 뜻입니다.

```powershell
bcdedit /enum | findstr /i hypervisorlaunchtype
```

결과가 `Off`가 아니라면 1.1.4절의 3단계를 관리자 권한으로 다시 실행하고 재부팅합니다. `Off`인데도 거북이 아이콘이 보인다면 6단계의 메모리 무결성 설정을 확인합니다.

### 문제 3. `enp0s8`에 IP 주소가 없습니다

설치 중 1.3.4절 ⑥단계에서 두 번째 장치를 ON으로 켜지 않은 경우가 대부분입니다. 연결을 켜고, 부팅할 때마다 자동으로 연결되도록 설정합니다.

```bash
nmcli device status                                         # 장치 상태 확인 (disconnected인지 확인)
sudo nmcli connection modify enp0s8 connection.autoconnect yes
sudo nmcli connection up enp0s8
ip addr show enp0s8                                         # IP 주소 확인
```

이래도 IP가 없다면 VirtualBox 네트워크 관리자에서 호스트 전용 네트워크의 **DHCP 서버**가 켜져 있는지 확인합니다(1.2.2절).

### 문제 4. 인터넷이 안 됩니다 (`ping 8.8.8.8` 실패)

| 확인할 것 | 방법 |
|---|---|
| 어댑터 1이 NAT인가 | VM 설정 → 네트워크 → 어댑터 1 |
| `enp0s3`이 연결되어 있는가 | `nmcli device status` |
| Windows 자체의 인터넷이 되는가 | Windows 브라우저로 확인 |

`enp0s3`이 끊어져 있다면 문제 3과 같은 방법으로 `enp0s3`을 연결합니다.

### 문제 5. 비밀번호가 맞는데 로그인이 안 됩니다

| 원인 | 해결 |
|---|---|
| 키보드 배열이 달라 특수 문자가 다르게 입력됩니다 | 로그인 화면에서 사용자 이름 칸에 비밀번호를 그대로 입력해 보며 실제로 어떤 문자가 입력되는지 확인합니다 |
| Num Lock이 꺼져 있어 숫자 키패드가 입력되지 않습니다 | 키보드 상단의 숫자 키를 사용합니다 |

### 문제 6. 재부팅하면 다시 설치 화면이 나옵니다

ISO가 연결된 채로 재부팅했기 때문입니다. VM 창 메뉴의 **장치 → 광학 드라이브**에서 디스크를 꺼내고 재부팅합니다. 설치는 이미 끝났으므로 다시 설치할 필요가 없습니다.

### 문제 7. SSH 키를 등록했는데도 비밀번호를 묻습니다

```bash
ls -ld ~/.ssh                   # drwx------ 이어야 합니다 (700)
ls -l ~/.ssh/authorized_keys    # -rw------- 이어야 합니다 (600)
```

권한이 다르다면 바로잡습니다.

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
restorecon -Rv ~/.ssh           # SELinux 보안 정보 복구 (5.2절에서 자세히 배웁니다)
```

Windows에서 자세한 접속 과정을 보면 원인을 찾는 데 도움이 됩니다.

```powershell
ssh -v spring
```

### 문제 8. `ssh` 접속 시 "REMOTE HOST IDENTIFICATION HAS CHANGED" 경고가 나옵니다

VM을 다시 설치했거나 OVA로 가져와서 서버의 지문이 바뀐 경우입니다. 내가 직접 바꾼 서버가 확실하다면, 저장된 예전 지문을 지웁니다.

```powershell
ssh-keygen -R 192.168.56.101
```

> **주의:** 실무에서 이 경고가 예고 없이 나타난다면, 누군가 중간에서 접속을 가로채고 있을 가능성도 있습니다. 서버 관리자에게 확인하기 전에는 지문을 지우지 마십시오.

## 확인 문제

**1.** WSL2가 실행 중인 PC에서 VirtualBox VM이 매우 느리게 동작하는 이유로 가장 알맞은 것은 무엇입니까?

1. VM에 할당한 메모리가 부족하기 때문입니다
2. Hyper-V가 CPU 가상화 기능을 차지하여 VirtualBox가 직접 사용할 수 없기 때문입니다
3. NAT 어댑터가 인터넷 속도를 제한하기 때문입니다
4. Rocky Linux가 VirtualBox를 지원하지 않기 때문입니다

**2.** Windows에서 VM으로 SSH 접속을 할 때 사용하는 네트워크 어댑터는 무엇입니까?

1. NAT
2. 호스트 전용 어댑터
3. 브리지 어댑터
4. 내부 네트워크

**3.** 프롬프트 `[devuser@spring-server ~]$`에서 `$` 기호가 뜻하는 것은 무엇입니까?

1. 관리자(root)로 로그인했습니다
2. 명령이 실행 중입니다
3. 일반 사용자로 로그인했습니다
4. 홈 디렉터리에 있습니다

**4.** SSH 키 인증에 대한 설명으로 **틀린** 것은 무엇입니까?

1. 공개 키는 서버의 `~/.ssh/authorized_keys`에 등록합니다
2. 개인 키는 접속하는 PC에만 보관합니다
3. 개인 키를 서버에 등록해야 접속할 수 있습니다
4. `~/.ssh` 디렉터리의 권한이 느슨하면 키 인증이 거부될 수 있습니다

**5.** 다른 PC로 VM 전체를 옮기기에 가장 알맞은 방법은 무엇입니까?

1. 스냅샷 만들기
2. 연결된 복제
3. OVA로 내보내기
4. 헤드리스 시작

1. **2번.** CPU 가상화 기능은 하나의 하이퍼바이저만 직접 사용할 수 있습니다. WSL2 때문에 Hyper-V가 켜져 있으면 VirtualBox는 Hyper-V를 거쳐 실행되므로 느려집니다.
2. **2번.** 호스트 전용 어댑터는 Windows와 VM을 직접 연결하는 사설 네트워크입니다. NAT는 VM에서 밖으로 나가는 연결에만 사용되므로 Windows에서 VM으로 바로 들어올 수 없습니다.
3. **3번.** 일반 사용자는 `$`, root는 `#`으로 표시됩니다. 홈 디렉터리에 있다는 것은 `~`가 나타냅니다.
4. **3번.** 서버에 등록하는 것은 공개 키입니다. 개인 키는 절대 다른 곳에 복사하거나 공유하지 않습니다.
5. **3번.** 스냅샷과 연결된 복제는 원본 디스크에 의존합니다. OVA는 설정과 디스크를 파일 하나로 묶으므로 다른 PC로 옮기거나 보관하기에 알맞습니다.
