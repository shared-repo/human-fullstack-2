## 1. React 소개

### 1.1 React란?
- Meta(구 Facebook)에서 개발한 UI 라이브러리
- "선언형(Declarative)" 방식으로 UI를 작성: 상태(state)가 바뀌면 화면이 자동으로 갱신됨
- 컴포넌트(Component) 단위로 화면을 구성 - 재사용 가능한 UI 조각

### 1.2 왜 React를 사용하는가
- 기존 jQuery/Vanilla JS 방식: DOM을 직접 조작 → 코드가 복잡해지고 유지보수 어려움
- React 방식: 데이터(상태)만 바꾸면 화면이 자동으로 반영 → 코드 가독성과 유지보수성 향상
- 컴포넌트 재사용으로 개발 속도 향상
- 풍부한 생태계 (React Router, 상태관리 라이브러리, UI 라이브러리 등)

### 1.3 SPA(Single Page Application) 개념
- 전통적인 방식(MPA, Multi Page Application): 페이지 이동 시마다 서버에서 새로운 HTML을 받아와 화면 전체를 다시 그림
- SPA 방식: 최초 1번만 HTML을 로드하고, 이후에는 필요한 데이터만 서버에서 받아와 화면의 일부만 갱신
- 장점: 빠른 화면 전환, 부드러운 사용자 경험(UX)
- 단점: 초기 로딩 시간이 길 수 있음, SEO 처리에 추가 작업 필요

### 1.4 React 동작 방식 개요 (간단히)
- Virtual DOM 개념 소개 (실제 DOM과 비교해 변경된 부분만 효율적으로 업데이트)
- 컴포넌트 → 상태(state) 변경 → 리렌더링(re-render)의 큰 흐름만 짧게 소개 (상세 내용은 3일차에서 다룸)

## 2. 개발 환경 구축

### 2.1 사전 준비 확인
- Node.js, npm 버전 확인
  ```bash
  node -v
  npm -v
  ```
- 코드 에디터: VS Code 권장 (확장: ES7+ React/Redux snippets, Prettier 등)

### 2.2 Vite로 프로젝트 생성
- Vite 소개: Create React App 대비 빠른 빌드/개발 서버
- 프로젝트 생성 명령어
  ```bash
  npm create vite@latest my-first-react -- --template react
  cd my-first-react
  npm install
  npm run dev
  ```
- 개발 서버 접속 확인 (브라우저에서 `http://localhost:5173`)

### 2.3 프로젝트 폴더 구조 살펴보기
- `index.html`: 진입점 HTML
- `src/main.jsx`: React 앱이 렌더링되는 시작점
- `src/App.jsx`: 최상위 컴포넌트
- `src/assets`, `public`: 정적 자원 폴더
- `package.json`: 프로젝트 설정 및 의존성 관리

## 3. JSX 문법

### 3.1 JSX란?
- JavaScript 안에서 HTML과 유사한 문법으로 UI를 작성할 수 있게 해주는 문법 확장
- 빌드 과정에서 `React.createElement()` 호출로 변환됨 (개념만 소개)

### 3.2 JSX 작성 규칙
- 반드시 하나의 최상위 요소로 감싸야 함 (또는 Fragment `<>...</>` 사용)
- JS 표현식은 `{ }`로 감싸서 사용
- 속성명은 camelCase 사용 (`class` → `className`, `onclick` → `onClick`)
- 모든 태그는 닫아야 함 (`<img />`, `<br />`)

### 3.3 예제 코드

```jsx
function App() {
  const userName = "홍길동";
  const isLoggedIn = true;

  return (
    <div className="container">
      <h1>안녕하세요, {userName}님!</h1>
      {isLoggedIn ? <p>로그인 상태입니다.</p> : <p>로그인이 필요합니다.</p>}
    </div>
  );
}

export default App;
```

### 3.4 자주 하는 실수
- 최상위 요소 누락
- `class` 속성 사용 (→ `className`으로 작성해야 함)
- 주석 작성법: `{/* 주석 */}`

## 4. 컴포넌트 기본 구조

### 4.1 컴포넌트란?
- 재사용 가능한 UI 조각 (함수 형태)
- 함수형 컴포넌트: 이름은 대문자로 시작, JSX를 반환하는 함수

```jsx
function Greeting() {
  return <h2>환영합니다!</h2>;
}
```

### 4.2 컴포넌트 분리와 조합
- 큰 화면을 작은 컴포넌트로 나누는 이유: 재사용성, 가독성, 유지보수성
- 컴포넌트를 다른 컴포넌트 안에서 사용하기

```jsx
function Header() {
  return <header><h1>My Site</h1></header>;
}

function Footer() {
  return <footer><p>© 2026 My Site</p></footer>;
}

function App() {
  return (
    <div>
      <Header />
      <main>본문 내용</main>
      <Footer />
    </div>
  );
}
```

### 4.3 파일 분리
- 컴포넌트를 별도 파일(`.jsx`)로 분리하고 `export`/`import` 하는 방법
- 폴더 구조 예시: `src/components/Header.jsx`, `src/components/Footer.jsx`

```jsx
// Header.jsx
function Header() {
  return <header><h1>My Site</h1></header>;
}

export default Header;
```

```jsx
// App.jsx
import Header from './components/Header';

function App() {
  return (
    <div>
      <Header />
    </div>
  );
}

export default App;
```
