## 1. 데이터 · 정보 · 지식

### 1.1 데이터 (Data)

**데이터**란 현실 세계에서 관찰하거나 측정한 **가공되지 않은 사실(raw fact)**이다.  
그 자체로는 의미가 명확하지 않으며, 숫자·문자·이미지·소리 등 다양한 형태로 존재한다.

| 예시 | 설명 |
|---|---|
| `36.5` | 숫자 자체만으로는 무엇을 의미하는지 알 수 없다 |
| `홍길동` | 이름인지, 캐릭터 이름인지, 아이디인지 알 수 없다 |
| `2024-03-15` | 날짜인지, 코드인지 알 수 없다 |

> **핵심 포인트**: 데이터는 맥락(context) 없이는 의미를 갖지 못한다.

---

### 1.2 정보 (Information)

**정보**란 데이터를 **특정 목적에 맞게 처리·가공**하여 의미를 부여한 결과물이다.  
데이터에 맥락이 더해지면 정보가 된다.

```
데이터  →  처리·가공  →  정보
```

| 데이터 | 처리 | 정보 |
|---|---|---|
| `36.5` | "체온 측정값" 맥락 추가 | "정상 체온(36.5°C)" |
| `홍길동, 2024-03-15, 36.5` | 환자 기록으로 정리 | "홍길동 환자가 2024년 3월 15일에 체온 36.5°C를 기록함" |
| 쇼핑몰 클릭 기록 수천 건 | 상품별 집계 | "이번 주 가장 많이 클릭된 상품 TOP 10" |

---

### 1.3 지식 (Knowledge)

**지식**이란 축적된 정보를 바탕으로 도출한 **규칙·패턴·판단**이다.  
정보를 반복적으로 접하고 경험이 쌓이면 지식이 된다.

```
데이터  →  정보  →  지식
```

**예시로 이해하기**

> 편의점 CCTV를 통해 매일 고객 방문 시간대를 기록한다고 가정하자.

- **데이터**: 07:32 입장, 07:45 입장, 07:51 입장, 12:03 입장, 12:11 입장 …
- **정보**: 오전 7~8시에 32명, 낮 12~13시에 58명 방문
- **지식**: "이 편의점은 점심시간 방문객이 가장 많다. 해당 시간대에 직원을 추가 배치하고 도시락·음료 재고를 늘려야 한다."

> **핵심 포인트**: 지식은 의사결정의 근거가 된다. 데이터베이스는 데이터를 체계적으로 저장하여 정보와 지식을 빠르고 정확하게 추출할 수 있도록 돕는 도구다.

---

### 1.4 DIKW 피라미드

데이터·정보·지식의 관계를 시각적으로 표현한 모델이다.

```
        △
       /  \
      / 지혜 \        ← Wisdom  : 지식을 바탕으로 한 올바른 판단
     /────────\
    /   지식   \      ← Knowledge: 정보에서 도출한 규칙·패턴
   /────────────\
  /    정보      \    ← Information: 가공·처리된 데이터
 /────────────────\
/      데이터      \  ← Data: 가공되지 않은 사실
────────────────────
```

> 이 강의에서는 데이터베이스를 활용하여 데이터 → 정보 → 지식으로 이어지는 과정을 직접 실습한다.

## 2. 데이터베이스와 DBMS

### 2.1 파일로 데이터를 관리하면 어떤 문제가 생길까?

데이터베이스를 배우기 전에, 왜 필요한지를 먼저 이해하는 것이 중요하다.

**시나리오**: 학원에서 엑셀 파일로 수강생 정보를 관리한다고 가정하자.

| 문제 | 설명 |
|---|---|
| **중복 저장** | 같은 수강생이 여러 강좌를 수강하면 이름·연락처가 여러 파일에 중복 저장된다. 연락처가 바뀌면 모든 파일을 일일이 수정해야 한다. |
| **동시 접근 불가** | 두 명의 직원이 동시에 같은 파일을 수정하면 한 명의 변경 내용이 사라진다. |
| **보안 취약** | 파일을 복사하면 모든 데이터가 그대로 노출된다. 특정 직원에게 특정 데이터만 보여주기 어렵다. |
| **검색 속도** | 수강생이 수천 명이 되면 엑셀에서 원하는 데이터를 찾는 속도가 느려진다. |
| **데이터 정합성** | 입력 형식이 제각각이 되기 쉽다. (전화번호: 010-1234-5678 / 01012345678 / 010.1234.5678) |

---

### 2.2 데이터베이스 (Database, DB)

**데이터베이스**란 여러 사람이 공유하여 사용할 목적으로 **체계적으로 구조화하여 저장한 데이터의 집합**이다.

주요 특징:

- **통합성**: 동일한 데이터를 중복 없이 한 곳에 저장한다.
- **공유성**: 여러 사용자가 동시에 접근할 수 있다.
- **지속성**: 프로그램이 종료되어도 데이터가 유지된다.
- **보안성**: 접근 권한을 사용자별로 세밀하게 제어할 수 있다.
- **무결성**: 잘못된 데이터가 저장되지 않도록 규칙을 설정할 수 있다.

---

### 2.3 DBMS (Database Management System)

**DBMS**란 데이터베이스를 생성하고 관리하는 **소프트웨어 시스템**이다.  
사용자나 응용 프로그램이 데이터베이스에 직접 접근하는 것이 아니라, DBMS를 통해 데이터를 저장·조회·수정·삭제한다.

```
사용자 / 응용 프로그램
         ↕
       DBMS
         ↕
      데이터베이스 (저장 장치)
```

**대표적인 DBMS**

| DBMS | 제조사 | 특징 |
|---|---|---|
| Oracle | Oracle | 대형 엔터프라이즈 환경, 높은 안정성 |
| MySQL | Oracle | 오픈소스, 웹 서비스에 널리 사용 |
| **MariaDB** | MariaDB Foundation | MySQL 기반 오픈소스, 이 강의의 주제 |
| PostgreSQL | 커뮤니티 | 오픈소스, 고급 기능 지원 |
| MS SQL Server | Microsoft | Windows 환경, 기업용 |
| SQLite | 커뮤니티 | 경량형, 파일 기반, 모바일 앱에 사용 |

---

### 2.4 데이터베이스의 종류

DBMS는 데이터를 저장하는 방식에 따라 크게 두 가지로 나뉜다.

**관계형 데이터베이스 (RDBMS)**
- 데이터를 **테이블(표)** 형태로 저장
- 테이블 간의 **관계(Relationship)**를 통해 데이터를 연결
- SQL이라는 표준 언어를 사용
- 예: Oracle, MySQL, MariaDB, PostgreSQL

**비관계형 데이터베이스 (NoSQL)**
- 테이블 형태가 아닌 문서·키-값·그래프 등 다양한 형태로 저장
- 대용량·비정형 데이터 처리에 강점
- 예: MongoDB (문서형), Redis (키-값형), Neo4j (그래프형)

> 이 강의에서는 **관계형 데이터베이스(RDBMS)**인 MariaDB를 학습한다.

## 3. 관계형 데이터베이스의 구조

관계형 데이터베이스는 데이터를 **테이블(표)** 형태로 저장한다.  
엑셀의 시트와 비슷하게 생겼지만, 훨씬 엄격한 규칙이 적용된다.

### 3.1 테이블 (Table)

**테이블**은 관계형 데이터베이스에서 데이터를 저장하는 기본 단위다.  
같은 종류의 데이터를 행(가로)과 열(세로)로 구성한 2차원 구조다.

예시: `학생` 테이블

| 학생번호 | 이름   | 생년월일   | 연락처        | 주소     |
|:-------:|:-----:|:---------:|:------------:|:-------:|
| 1001    | 홍길동 | 1995-03-15 | 010-1234-5678 | 서울시 강남구 |
| 1002    | 김영희 | 1998-07-22 | 010-9876-5432 | 경기도 수원시 |
| 1003    | 이철수 | 1992-11-05 | 010-5555-7777 | 부산시 해운대구 |

---

### 3.2 행 (Row)

**행(Row)**은 테이블에서 **가로 한 줄**로, 하나의 데이터 항목(개체)을 나타낸다.  
**레코드(Record)** 또는 **튜플(Tuple)**이라고도 한다.

위 예시에서 `1002 | 김영희 | 1998-07-22 | 010-9876-5432 | 경기도 수원시`는 한 명의 학생에 대한 정보를 담은 하나의 행이다.

---

### 3.3 열 (Column)

**열(Column)**은 테이블에서 **세로 한 줄**로, 데이터의 **속성(Attribute)**을 나타낸다.  
**필드(Field)**라고도 한다.

위 예시에서 `이름` 열은 모든 학생의 이름을 저장하는 열이다.  
각 열은 저장할 수 있는 **데이터 유형**이 정해져 있다. (예: 학생번호는 숫자, 이름은 문자)

---

### 3.4 기본 키 (Primary Key, PK)

**기본 키**란 테이블에서 각 행을 **유일하게 식별**할 수 있는 열(또는 열의 조합)이다.

기본 키의 규칙:
- **유일성**: 같은 값이 두 번 나올 수 없다.
- **NOT NULL**: 반드시 값이 있어야 한다. 비어 있을 수 없다.

위 예시에서 `학생번호`가 기본 키다.  
이름은 동명이인이 있을 수 있으므로 기본 키로 적합하지 않다.

> **비유**: 기본 키는 주민등록번호와 같다. 모든 사람은 고유한 주민등록번호를 가지며, 비어 있을 수 없다.

---

### 3.5 외래 키 (Foreign Key, FK)

**외래 키**란 다른 테이블의 기본 키를 참조하는 열로, 두 테이블 사이의 **관계를 연결**하는 역할을 한다.

예시: `수강` 테이블

| 수강번호 | **학생번호** | 강좌명          | 수강일     |
|:-------:|:----------:|:--------------:|:---------:|
| 5001    | 1001       | MariaDB 기초    | 2024-03-04 |
| 5002    | 1002       | MariaDB 기초    | 2024-03-04 |
| 5003    | 1001       | Python 데이터분석 | 2024-03-04 |

`수강` 테이블의 `학생번호`는 `학생` 테이블의 `학생번호(PK)`를 참조하는 **외래 키(FK)**다.  
이를 통해 수강 기록과 학생 정보를 연결할 수 있다.

```
학생 테이블                    수강 테이블
┌──────────┬──────┐           ┌──────────┬──────────┬──────────┐
│ 학생번호 │ 이름  │           │ 수강번호  │ 학생번호  │  강좌명   │
│  (PK)   │      │◀──────────│          │  (FK)   │          │
├──────────┼──────┤           ├──────────┼──────────┼──────────┤
│  1001   │ 홍길동│           │  5001   │  1001   │ MariaDB  │
│  1002   │ 김영희│           │  5002   │  1002   │ MariaDB  │
└──────────┴──────┘           └──────────┴──────────┴──────────┘
```

---

### 3.6 용어 정리

| 공식 용어 | 일반적으로 사용하는 용어 | 설명 |
|:--------:|:-------------------:|:---:|
| 릴레이션 (Relation) | 테이블 (Table) | 데이터를 저장하는 기본 단위 |
| 튜플 (Tuple) | 행 (Row) / 레코드 (Record) | 하나의 데이터 항목 |
| 속성 (Attribute) | 열 (Column) / 필드 (Field) | 데이터의 특성 |
| 도메인 (Domain) | 데이터 유형 (Data Type) | 열에 저장할 수 있는 값의 범위 |

## 4. MariaDB 소개

### 4.1 MariaDB의 탄생

MariaDB는 **MySQL에서 분기(fork)된 오픈소스 관계형 데이터베이스**다.

**탄생 배경**:

1. MySQL은 원래 스웨덴 회사 **MySQL AB**가 개발한 오픈소스 DBMS였다.
2. 2008년 MySQL AB가 **Sun Microsystems**에 인수되었다.
3. 2010년 Sun Microsystems가 **Oracle**에 인수되면서, 오픈소스 커뮤니티는 Oracle이 MySQL의 오픈소스 정책을 변경할 것을 우려했다.
4. MySQL의 원래 개발자인 **Michael "Monty" Widenius**가 2009년 MySQL 코드를 기반으로 **MariaDB**를 만들었다.
5. 이름 "Maria"는 Widenius의 둘째 딸 이름에서 따왔다. (MySQL의 "My"는 첫째 딸 이름)

---

### 4.2 MariaDB의 주요 특징

| 특징 | 설명 |
|---|---|
| **완전한 오픈소스** | GPL 라이선스, 무료로 사용 가능 |
| **MySQL 호환성** | MySQL과 명령어·문법이 대부분 동일하여 전환이 쉽다 |
| **높은 성능** | MySQL보다 일부 작업에서 더 빠른 성능을 제공 |
| **다양한 스토리지 엔진** | InnoDB, Aria, MyRocks 등 다양한 엔진 선택 가능 |
| **활발한 커뮤니티** | 오픈소스 커뮤니티의 지속적인 개발과 지원 |
| **기업 지원** | MariaDB Corporation의 상용 지원 서비스 제공 |

---

### 4.3 MariaDB vs MySQL

MariaDB와 MySQL은 매우 유사하지만 몇 가지 차이가 있다.

| 항목 | MariaDB | MySQL |
|---|---|---|
| 개발 주체 | MariaDB Foundation (오픈소스) | Oracle (상용) |
| 라이선스 | GPL (완전 오픈소스) | GPL / 상용 (이중 라이선스) |
| 성능 | 일부 쿼리에서 빠름 | 안정적 |
| 새 기능 | 더 빠르게 추가 | 보수적으로 추가 |
| JSON 지원 | 지원 | 지원 |
| SQL 문법 호환성 | 거의 동일 | — |

> **결론**: 이 강의에서 MariaDB를 배우면 MySQL도 함께 배우는 것과 다름없다. 두 DBMS의 SQL 문법은 95% 이상 동일하다.

---

### 4.4 MariaDB의 활용 사례

MariaDB는 전 세계 수많은 서비스에서 사용되고 있다.

- **웹 서비스**: 블로그, 쇼핑몰, 커뮤니티 사이트의 회원 정보, 게시글, 주문 데이터 저장
- **금융**: 거래 내역, 계좌 정보 관리
- **의료**: 환자 정보, 진료 기록 관리
- **공공기관**: 민원 처리, 행정 데이터 관리
- **게임**: 사용자 계정, 아이템, 게임 로그 저장

> **취업 관점**: MariaDB와 MySQL은 중소기업·스타트업에서 가장 널리 사용되는 DBMS다. 이 기술을 익히면 다양한 직종(개발자, 데이터 분석가, DB 관리자)에서 활용할 수 있다.

## 장 요약

| 개념 | 핵심 내용 |
|---|---|
| **데이터** | 가공되지 않은 사실, 맥락 없이 의미 불명확 |
| **정보** | 데이터를 처리·가공하여 의미를 부여한 결과 |
| **지식** | 정보에서 도출한 규칙·패턴·판단, 의사결정의 근거 |
| **데이터베이스** | 체계적으로 구조화하여 저장된 데이터의 집합 |
| **DBMS** | 데이터베이스를 생성·관리하는 소프트웨어 |
| **테이블** | 행과 열로 구성된 데이터 저장 단위 |
| **행 (Row)** | 하나의 데이터 항목 (레코드, 튜플) |
| **열 (Column)** | 데이터의 속성 (필드, 속성) |
| **기본 키 (PK)** | 행을 유일하게 식별하는 열, 중복·NULL 불가 |
| **외래 키 (FK)** | 다른 테이블의 PK를 참조하여 테이블 간 관계 연결 |
| **MariaDB** | MySQL 기반 오픈소스 RDBMS, MySQL과 높은 호환성 |
